# Telegram CRM — правила агентной команды

## Общие правила

- Работай только в feature-ветке; `main` изменяется через Pull Request.
- Не выводи и не коммить значения из `.env`, токены, cookies и персональные данные.
- Не удаляй данные и не выполняй production-операции без явного разрешения.
- Перед кодом зафиксируй требования и критерии приёмки.
- Изменение API, ролей, БД или AI pipeline сопровождай тестами.
- После изменений запускай `npm run check` и указывай результат.
- Для миграций БД используй повторяемые операции; перед опасной миграцией нужен backup.

## Порядок работы над новой функцией

`analyst → product-manager → ux-expert → architect → security → developer → qa → product-owner → release-manager`

Для небольшого бага допускается `developer → qa → release-manager`. Оркестратор выбирает сокращённый путь только после классификации задачи.

## Артефакты

Крупная функция хранится в `docs/features/<feature>/` и содержит `requirements.md`, `design.md`, `tasks.md` и `test-plan.md`.

## Skills

Проектные Skills находятся в `agent-rules/skills/<role>/SKILL.md`. Если среда поддерживает локальные skills, подключи каталог `agent-rules/skills`; иначе вызывай skill по имени явно в запросе.

## Границы ролей

- Analyst, PM, UX, Architect и Security сначала готовят документы и не меняют production-код.
- Developer изменяет только согласованный scope и добавляет тесты.
- QA не ослабляет проверки ради зелёного результата.
- Product Owner проверяет критерии приёмки.
- Release Manager не пропускает релиз без тестов, документации и плана отката.
