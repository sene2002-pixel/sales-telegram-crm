# Telegram CRM — правила разработки

- Работай в feature-ветке; main обновляется через Pull Request.
- Сохраняй несвязанные пользовательские изменения.
- Не выводи и не коммить секреты, cookies, `.env` и персональные данные.
- Серверные права — источник истины; UI не заменяет авторизацию.
- Не удаляй данные и не выполняй production-операции без явного разрешения.
- Перед реализацией зафиксируй требования и критерии приёмки; меняй API, роли, БД и AI pipeline вместе с проверками.
- Выполняй релевантные проверки и `npm run check` перед выпуском, честно указывай пропуски и ошибки.
- Миграции должны быть повторяемыми; опасные изменения требуют backup и плана отката.

## Процесс

Для функций и существенных изменений используется глобальный development-orchestrator: `/Users/v.savin/.codex/skills/development-orchestrator/SKILL.md`. Это единственный источник адаптивной глубины, этапов ролей, независимого ревью и контрольных точек. Пользовательские инструкции имеют приоритет. Отдельные агенты используются только при разрешении сессии. Обычное ревью не разрешает реализацию или выпуск.

Сводную запись требований, решений, ревью, проверок и отката храни в `docs/features/<feature>/workflow.md`. Каталог `agent-rules/` содержит дополнительные справочники ролей и необязательные шаблоны; он не вводит отдельные согласования и не дублирует обязательный процесс.
