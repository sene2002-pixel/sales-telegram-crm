# Надёжная очередь запросов

PostgreSQL — источник истины; Kafka не требуется. `reports` хранит входящие задания, `dialogue_actions` — подтверждаемые действия и `depends_on`, `letter_jobs` — подготовку/доставку писем. Уведомления отправляются через существующий outbox.

Шаги одного запроса выполняются последовательно. Отдельные запросы по одной компании также ждут друг друга; неизвестная компания считается потенциальным конфликтом. Изменения подписей упорядочены с письмами. Разные компании могут обрабатываться независимо. Каждое действие требует подтверждения. Лимит — пять незавершённых действий сотрудника, включая выполняющиеся. Уточнение через «Редактировать запрос» занимает прежнее место, даже при 5/5; одновременно редактируется одна задача.

`WORKER_CONCURRENCY=3` задаёт число слотов каждого фонового обработчика на экземпляр приложения (1–10). Входящие сообщения одного сотрудника разбираются по порядку, чтобы сохранить контекст. Длительное выполнение независимых писем допускает параллельность. SQL-блокировки, leases и проверки статусов защищают от одновременного захвата; просроченные leases позволяют повторить обработку после перезапуска. Зависимый шаг письма ждёт сохранения PDF и подтверждённой доставки.

`request_history` сохраняет исходный текст, распознанный текст, Telegram file ID и связь уточнения с задачей. `request_events` содержит этапы планирования, уточнения, подтверждения, завершения, отмены и повторов. Байты голосовых и изображений в историю не копируются. `REQUEST_RETENTION_DAYS=30` — срок хранения от получения каждого сообщения. Worker удаляет истёкшую историю и события, очищает исходные данные завершённых dialogue reports. Рабочее состояние незавершённых задач сохраняется для выполнения. Карточки, контакты, активности и PDF не удаляются. Диагностические логи имеют отдельную политику хранения.

Нужны постоянный том PostgreSQL и резервные копии: очередь не заменяет бэкапы. Потеря ответа Telegram после фактической доставки может привести к повторной отправке при повторе — гарантии exactly-once для внешнего API нет. Ошибка зависимого шага блокирует его цепочку, но не независимые запросы; повтор требует предусмотренного подтверждения.
