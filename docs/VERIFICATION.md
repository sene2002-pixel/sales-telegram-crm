# Проверка реализации

Дата локальной проверки: 15 сентября 2026. Ветка: `feat/telegram-crm-platform`.

## Выполнено локально

- `npm run check`: успешная серверная и клиентская TypeScript-сборка; 25 тестов проходят на встроенном PostgreSQL PGlite.
- `npm run test:e2e`: 4 браузерных сценария проходят в Chromium, desktop и мобильный viewport iPhone 13. Проверены вход, создание компании и задачи, редактирование компании, сохранность после reload, доступ администратора к команде и отсутствие горизонтального переполнения.
- Автоматические тесты проверяют подпись/срок Telegram initData, подмену сессии, изоляцию компаний и связанных записей, stale writes, уникальность ИНН, передачу задач, откат многоблочного отчёта, идемпотентность webhook/подтверждения, lease/retry, устаревшие кнопки бота, защищённые вложения, CSV и отзыв доступа.
- Голосовой тракт проверен с тестовыми адаптерами. Контракт OpenAI (multipart, JSON Schema, refusal) проверен без отправки платных запросов.
- `npm run format:check` проходит. `git diff --check` не обнаруживает ошибок пробелов.
- npm после обновления NestJS/Multer: 0 известных уязвимостей на момент установки.
- `.venv/bin/python scripts/backup.py --help` и компиляция Python-скрипта проходят. `.venv` создано на Python 3.13.11.
- Приложение запущено локально на `http://localhost:3000`; данные хранятся в `data/postgres`.

## Проверки CI

Workflow настроен на повторную проверку на обычном PostgreSQL 17 в отдельной временной схеме, а также на PGlite, сборку, audit и браузерные сценарии. Результат удалённого запуска нужно смотреть в PR: наличие workflow не означает, что он уже прошёл.

## Требует реального окружения

- Настройка BotFather, публичного HTTPS webhook и live-проверка голосового сообщения в Telegram.
- Реальный вызов OpenAI с пользовательским API-ключом и оценка качества распознавания/извлечения на примерах команды.
- Проверка нативных Telegram iOS/Android: мобильная эмуляция Chromium не заменяет эти клиенты.
- Docker production-запуск и пробное восстановление PostgreSQL + вложений из резервной копии. Локальный Docker daemon не был запущен во время разработки.
- Политика хранения данных, мониторинг инфраструктуры и защита main на стороне GitHub.

В `.env.example` перечислены необходимые параметры. Секреты и рабочие данные не включаются в коммит. Код и инструкции всех этапов подготовлены; перечисленные проверки внешней инфраструктуры не выдаются за выполненное развёртывание.
