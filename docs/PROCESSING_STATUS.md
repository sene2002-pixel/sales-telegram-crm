# Временные статусы обработки Telegram

## Поведение

- Один статус на `source_key` запроса. Голосовой запрос и созданное из него письмо используют общий ключ.
- Статус отражает этап: распознавание, анализ запроса/подписи/контакта, подготовку черновика, поиск компании, формирование PDF или ожидание повторной попытки.
- Обновляется существующее сообщение без звукового уведомления при создании. Имена, телефоны, расшифровка и технические ошибки в статус не включаются.
- Перед результатом, уточняющим вопросом или ошибкой статус удаляется. Перед непосредственной отправкой PDF выполняется такая же очистка. Быстрые задачи не показывают уже устаревший статус.
- Отмена закрывает статус; результат старого обработчика не восстанавливает его. Повтор вручную получает новую генерацию, поэтому отложенное сообщение об ошибке предыдущей попытки не удалит новый статус.

## Устройство

`processing_messages` — долговечная очередь текущего состояния: ключ запроса, чат, текущий текст, активность, поколение, Telegram `message_id`, доставленный текст и время следующей попытки. Создание/смена состояния входят в транзакции вместе с запросом. `AsyncLocalStorage` передаёт только ключ внутри исполнения, но не хранит состояние доставки.

Финальные сообщения по-прежнему записываются в `outbox`; поля `processing_key` и `processing_generation` связывают их с нужным статусом. Доставка держит блокировку строки статуса: сначала удаление, затем отправка результата. При временном сбое удаления результат не отправляется поверх старого статуса; работает обычная повторная доставка. Независимый цикл доставки продолжает работать во время длительного распознавания/поиска. После перезапуска идентификаторы читаются из БД.

Ошибки временного статуса записываются в `error_logs` с событием `telegram.processing_status_failed`; ошибки финальной доставки — `telegram.delivery_failed`. Сбой обновления статуса повторяется через 30 секунд и не отменяет бизнес-операцию. Если перед отправкой готового PDF временно не удаётся удалить статус, письмо остаётся `ready`, а попытка доставки не расходуется: файл не генерируется заново. Событие — `telegram.processing_cleanup_deferred`. Повторное удаление уже отсутствующего сообщения и повторное редактирование тем же текстом безопасны.

## Ограничения внешнего API

Используются обычные [sendMessage](https://core.telegram.org/bots/api#sendmessage), [editMessageText](https://core.telegram.org/bots/api#editmessagetext) и [deleteMessage](https://core.telegram.org/bots/api#deletemessage). Telegram ограничивает удаление по возрасту сообщения и правам бота. При явном постоянном запрете удаления (`message can't be deleted` / недостаточно прав на удаление) очистка делает исключение: фиксирует `telegram.processing_delete_forbidden` в БД с ключом запроса и ID сообщения, прекращает бессмысленные повторы удаления и пропускает результат. Старое сообщение при этом может остаться в Telegram; успешное удаление не заявляется. Сетевые ошибки, блокировка бота и неизвестные ошибки не выдаются за постоянный запрет удаления: очистка повторяется через 30 секунд.

Telegram Bot API не предоставляет ключ идемпотентности для `sendMessage`: при аварии после принятия сообщения Telegram, но до записи полученного `message_id` в БД, может остаться сообщение с неизвестным приложению ID. Обычный рестарт после фиксации транзакции поддерживается; абсолютная гарантия exactly-once через эту границу невозможна. Для сообщений с сохранённым ID используется повторяемая очистка.

## Проверка

`src/tests/processing-status.test.ts`: доставка во время заблокированного извлечения, редактирование одного ID, новый экземпляр обработчика, отмена во время обработки, сбой удаления/повтор, постоянный запрет удаления с записью исключения и доставкой результата, устаревший результат после ручного повтора, терминальная ошибка, подписи/контакты, передача голосового запроса в письмо и быстрые результаты. `src/tests/letter-bot.test.ts` проверяет, что шесть временных сбоев очистки перед PDF не расходуют попытки, не регенерируют файл и не мешают последующей доставке. Telegram и ИИ заменены локальными тестовыми реализациями; реальные сообщения не отправляются.
