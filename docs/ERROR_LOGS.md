# Журнал ошибок

Сервер автоматически создаёт таблицу `error_logs` при обновлении. Раздела в Mini App нет.

В журнал попадают ошибки HTTP API (включая проверки доступа и данных), обработки отчётов, доставки Telegram и получения адреса меню. Ошибки ИИ и генерации PDF, прерывающие запрос, сохраняются через общий обработчик API. Ошибки браузера, Docker, ОС и сбои до подключения БД эта таблица не собирает.

Поля: `id`, `created_at`, `event`, `request_id`, `actor_id`, `status`, `message`, `details`. ID сотрудника записывается после успешной аутентификации. `details` содержит тип исключения, шаблон маршрута либо ID фоновой задачи и номер попытки. Заголовок ответа `X-Request-ID` позволяет найти запрос.

Тела запросов, заголовки авторизации, URL с параметрами, контакты и документы не сохраняются. Сообщения внешних исключений и stack trace скрываются: они могут содержать секреты. Сохраняются безопасные сообщения ошибок, сформированные самим приложением. Журнал недоступен через HTTP API; доступ — через права БД.

При запуске сервера и затем каждый час удаляются записи старше **трёх календарных месяцев**. Очистка работает независимо от включения обработчика отчётов. Пока сервер выключен, очистка не выполняется. Срок хранения резервных копий БД настраивается отдельно.

Если запись в БД невозможна, безопасная запись выводится в stderr (логи Docker), без повторных попыток через тот же журнал. Сбой записи не должен заменять исходную ошибку API.

Последние ошибки:

```sql
SELECT created_at, event, status, message, request_id, actor_id, details
FROM error_logs
ORDER BY created_at DESC
LIMIT 100;
```
