# Pico: новые экраны Mini App

## Требования и решения

Источник: предоставленный пользователем PDF «Pico-макет-экраны», шесть страниц: Главная, Клиенты, Проекты, Задачи, Аналитика, иконки. Документ используется как визуальный и поведенческий образец. Системная рамка Telegram и демонстрационные имена/числа не воспроизводятся как данные CRM.

Объём: пять основных вкладок, компактные раскрывающиеся карточки, мобильные нижние шторки, новые поля задач и проектов, фильтры, аналитика реальных доступных клиентских данных. Существующие отчёты, документы, профиль, календарь и команда доступны через дополнительное меню. Desktop использует тот же интерфейс с боковой навигацией.

Критерии приёмки:

- Работают пять вкладок на desktop и mobile без горизонтального переполнения.
- Главная показывает реальные счётчики, сегодняшние задачи, встречи и начальные подсказки.
- Карточки клиентов раскрывают контакты, потенциал, файлы и заметки; изменения сохраняются и видны при повторном открытии.
- Задачи сохраняют тип, дату, время и выбранный контакт; выполнение и перенос сохраняют остальные поля; удаление проверяет версию и права.
- Проекты сохраняют объект, город, дату закупки, оборудование и участников с ролью, контактом, текущей задачей и следующим шагом; порядок участников сохраняется.
- Аналитика использует реальные стадии и потенциал; смысл периода и показателей явно указан, изменения относительно прошлых месяцев не выдумываются.
- Сервер проверяет принадлежность контактов и доступ к участникам проекта. Старые записи и запросы продолжают работать.
- Минимум два независимых тестировщика проверяют поведение и визуальную адаптацию, после исправлений повторяют затронутые проверки.

## Хранение и откат

Новые поля находятся в JSON существующих records; схема SQL не меняется, перенос данных не требуется. Старые записи получают значения по умолчанию при редактировании. Новые задачи: type=reminder, time/contactId=null. Новые поля проектов: пустые строки/списки, purchaseDate=null. Удаление задачи ставит deleted=true, повышает version и пишет аудит; физического удаления нет.

Откат к предыдущей версии требует проверки сохранённых JSON с новыми полями: старые strict-схемы могут отклонить редактирование таких записей. Перед выпуском сохранить резервную копию БД, при откате использовать совместимую схему либо восстановление резервной копии по отдельному разрешению. Новые поля нельзя незаметно удалять из пользовательских данных. Запуск production, удаление данных и восстановление не выполняются этим изменением.

## Проверки

`npm run check`: 325 passed, 2 skipped; 7 ops passed; сборка server/web прошла. Повторная сборка после заключительных UI-исправлений также прошла. В окружении без разрешения локального HTTP-listen Supertest получал EPERM; полный прогон с разрешением на тестовые порты прошёл. Имеющиеся предупреждения Vite о NODE_ENV и Rollup об аннотациях Zod не блокируют сборку.

Независимый тестировщик 1 проверил пять экранов по фактическим снимкам, сценарии desktop/mobile (6/6), узкий экран 360×640 (3/3), пустые состояния и поясняющие карточки (2/2). Покрытие: запись оборудования и участников, сохранение контакта, времени и проекта задачи после перезагрузки, переноса и выполнения; 503 без потери ввода; focus trap вложенной шторки. Заключительная проверка отмены/применения периода 2/2; сохранение неизвестной и смешанной суммы оборудования 2/2. Итог: принято, блокеров нет.

Полный итоговый `npm run test:e2e` на окончательной сборке: **60/60**, desktop 30/30, mobile 30/30. Кейс отмены периода, пустые состояния и неизвестные суммы включены.

Независимый тестировщик 2: серверные негативные тесты 4/4; проверки прав, новой/исторической ссылки, дублей, принадлежности контакта, stale version, soft-delete и аудита; независимый review фактического diff без оставшихся security-блокеров.

Исправления по проверкам: пустые новые формы больше не валидируются с обязательными пустыми значениями до ввода; выполнение задач сохраняет type/time/contactId; ссылки на удалённый контакт не блокируют выполнение старой задачи; редактирование исторического проекта не блокируется архивированным участником. Согласован порядок блокировок записи и компании. Убрана дублированная навигация и повторный ряд выбора месяца; мобильное меню сохраняет «Обновить» и «Права и помощь». Шторки вынесены в portal, чтобы вложенное оборудование не отправляло родительскую форму. Сумма проекта остаётся null при наличии оборудования без суммы, включая смешанные известные/неизвестные позиции; неизвестное не превращается в ноль. Выбор периода применяет черновик только кнопкой «Применить».

Регрессионные E2E адаптированы к новой навигации и accordion/sheet-сценариям с сохранением проверок поведения. Демо-вход для тестов переиспользуется только в памяти тестового worker, чтобы полный набор не расходовал лимит входа 30/мин; production-лимиты не менялись. Живые Telegram/OpenAI в этих прогонах отключены.

## Показатели аналитики

Воронка показывает **текущую стадию клиентов, созданных за выбранный период**, поскольку история переходов стадий отсутствует. Доля завершённых относится к этой же группе. Годовой потенциал — сумма указанных направлений всех доступных активных клиентов, независимо от выбранного периода. Отсутствующие суммы не заменяются вымышленными; динамика к прошлому месяцу не рассчитывается без исходных данных.

## Описание для PR

Обновить Mini App по новым экранам Pico: пять основных вкладок, раскрывающиеся клиентские и проектные карточки, шторки создания и фильтрации, календарь и действия задач, аналитика реальных CRM-данных. Добавить совместимые поля времени/типа/контакта задач и оборудования/участников проектов; защищать новые ссылки серверной проверкой доступа, удалять задачи через версионный soft-delete с аудитом.

Выпуск: перед публикацией резервная копия существующей БД и обычный smoke-check после согласованного обновления. Push, PR, merge, перезапуск сервиса и живые операции не выполнялись. Изменения подготовлены локально в `codex/pico-screen-mockups`.
