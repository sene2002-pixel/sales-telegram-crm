# Подтверждения архива и удаления

Источник: следующий подтверждённый баг из дизайн-аудита1ноября2026. Inline-подтверждение SwipeAction объявлялось alertdialog, но Escape его не отменял и Tab выводил фокус наружу. Архивирование клиента называлось удалением. Пользователь поручил исправить следующий баг; выпуск в main ранее разрешён. Отдельная карточка Asana для этой находки не создавалась.

## Решение и критерии

- Подтверждение использует общий Modal с role=alertdialog и aria-modal. Начальный фокус — «Отмена». Tab/Shift+Tab остаются внутри. Escape, крестик, фон, Telegram Back и «Отмена» отменяют без запроса, возвращая фокус к видимой кнопке свайпа. После отмены раскрытый свайп остаётся доступным.
- Для клиента: «Перенести клиента в архив?», имя объекта, вкладка «Закрытые», сохранность контактов/потенциала/заметок/файлов и возможность восстановления администратором. Основная команда и доступная подпись инициатора прямо говорят об архиве.
- Для контакта/оборудования/файла сохраняется действие удаления и конкретный объект в тексте. Общий короткий заголовок «Подтверждение удаления» не раздувается от длинного названия.
- Pending синхронно блокирует повторный запрос и все способы закрытия. Видны состояние команды и disabled-контролы. Ошибка остаётся внутри диалога, повтор разрешён после завершения запроса.
- Успех закрывает диалог и обновляет существующий список; данные и серверные права не меняются. Новые migrations/API/permissions отсутствуют.

## Технические риски и проверки

Два аналитика независимо выявили важный риск: React-события portal всплывают через React-дерево, даже когда DOM диалога находится в body. Modal вынесен соседним элементом из собственного swipe-wrapper; обработчики всех вложенных свайпов игнорируют события из модального корня. Это проверяется отдельным отменённым удалением оборудования, контакта и файла.

Владение клавиатурой/Telegram Back определяется только настоящими корнями общего Modal (`data-pico-modal`), включая alertdialog; старые inline-секции CompanyDetail не перехватывают владение. Сохранён общий счётчик блокировки прокрутки из предыдущего исправления черновиков. Home touchmove и расчёт области ввода учитывают alertdialog.

Два независимых ревьюера проверили actual diff. Найденный случайный вызов helper вне SwipeAction исправлен; TypeScript/Vite сборка прошла, повторные ревью одобрены. Изменены только необходимые portal-селекторы старых тестов, проверки API/версии/сохранности данных сохранены.

Два дизайнера просмотрели5реальных снимков первой итерации (архив320×568/390×844, ошибка, контакт, оборудование). По замечанию исправлен падеж в общем заголовке; оба дизайнера повторно просмотрели3кадра контакта, оборудования и файла, финальный PASS. Исходный Claude-холст не используется как доступный pixel-perfect источник.
