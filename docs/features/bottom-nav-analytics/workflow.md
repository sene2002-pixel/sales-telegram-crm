# Нижнее меню и аналитика

Источники: Asana [нижнее меню](https://app.asana.com/1/1218599458205876/project/1218585786925552/task/1219536520044168) и [открытая задача аналитики](https://app.asana.com/1/1218599458205876/project/1218585786925552/task/1219533367751834). Одноимённая завершённая задача аналитики не используется как актуальная постановка.

## Требования и решения

Доработать существующие экраны: меню 72px, иконки 26px, подписи 10.5/14, пять колонок до 72px с промежутками 2px; на узких экранах колонки сжимаются. Safe area увеличивает высоту, чтобы сохранить кнопки 48px над системной полоской.

Аналитика: сохранить существующие серверные восемь баллов, происхождение контактов, историю, права и сравнение периодов. Добавить раскрывающиеся уровни, первые три компании с потенциалом и переход к списку с фильтром. Фильтр сохраняет выбранный период и пересчитывается после изменения компаний; смена области/аккаунта его очищает. Недоступные серверу компании не подгружаются через отдельный обходной путь.

Трапеции сохраняют форму из приложенного HTML: 9px с каждой стороны (18px суммарно). Буквальные 18px с каждой стороны противоречат ширине 150px и приложенному SVG. Иконки строк оборудования остаются прежними: задача меняет только иконку заголовка.

Четыре KPI: сетка 2×2 с промежутками 8px, числа 26/28, компактные подписи; динамика рядом с числом. Карточки и раскрытые списки сохраняют естественную высоту при длинных данных и масштабировании. Геометрия первого экрана проверяется на свёрнутых блоках; раскрытие и сообщения об ограничениях истории требуют прокрутки.

## Продолжение списка внутри уровня

Актуальное требование заменяет прежний переход к вкладке «Клиенты»: список раскрывается на странице аналитики. Два аналитика независимо разобрали сценарии и границы. Первые три строки — предпросмотр; для 1–3 клиентов кнопка отсутствует, для 4–100 показывается весь список, для большего числа — максимум 100 строк. Заголовок сохраняет полный счётчик. При числе клиентов больше 100 доступен поиск по названию/ИНН, выполняемый по всем доступным клиентам уровня до ограничения отображения; отраслевой фильтр не добавлялся. «Свернуть» очищает поиск. Обновление периода/области размонтирует прежний список и сбрасывает его состояние.

UX/дизайн: существующие точки, имена и потенциал; поле поиска и счётчик результатов, компактная прокрутка списка до 360px/половины высоты экрана; клавиатурный фокус, aria-expanded/controls и подписи поля. Фактический мобильный рендер проверен ведущим после реализации. Архитектура/security: пересечение серверных IDs уровня с текущими доступными неархивными компаниями сохранено; лимит 100 относится к строкам UI, не к базе CRM или числу загружаемых записей. API и миграции не менялись. Старая навигация и эффект фильтра из main.tsx удалены.

Независимый Reviewer (второй аналитик после передачи реализации) проверил фактический diff — блокеров нет. QA/Acceptance: build, Prettier, diff check и 28/28 браузерных проверок desktop/mobile, включая 3/4/100/121, поиск клиента за пределом первых 100, ИНН, пустой результат, сворачивание, период,403 и геометрию. Откат — возврат UI-коммита, без изменения данных. Публикация продолжает запрошенную пользователем доставку аналитики в main; серверная пересборка остаётся отдельной операцией.

## Строка «Показать всех» в стиле списка

Три дизайнера независимо изучили существующий интерфейс и согласовали один вариант после обмена предложениями: прозрачная строка продолжения списка, а не отдельная плашка. Локальный класс исключает наследование общего .text-button; ширина100%, min-height44px, padding8px 0, текст13/18 w500 #1f7aea по краю имён компаний, шеврон16px рядом с gap6px. Нет рамки, скругления или тени; hover затемняет текст, active даёт лёгкую заливку, focus-visible показывает контур. Тексты и поведение сохранены, дополнительные счётчики/кнопка сворачивания отсутствуют.

Ведущий проверил фактический diff. Build, diff check и 8/8 desktop/mobile E2E прошли, в том числе CSS-геометрия, прозрачность, отсутствие рамки и декоративная иконка. Сервер, API и база не меняются; откат — возврат этого UI-коммита.

## Исправление прокрутки в Telegram Desktop

Диагностика колеса воспроизвела блокировку на уровне из6 клиентов: список полностью помещался (180px), но overscroll-behavior:contain удерживал колесо, хотя документ имел777px доступной прокрутки. Временное снятие contain разблокировало страницу. Удалены max-height, overflow-y:auto, overscroll containment и scrollbar-gutter у раскрытого списка: остаётся единая прокрутка страницы. Лимит100 и поиск сохранены. Порционная выдача и независимый риск сброса состояния при focus не включены в это исправление.

Ведущий проверил точечный CSS-diff. Build, diff check и браузерные проверки аналитики выполнены, добавлены регрессии колеса для6/121 клиентов и достижимости следующего раздела. Desktop-специфичные wheel-сценарии намеренно пропускаются в mobile-проекте. Нативный Telegram Desktop после серверной пересборки требует контрольной проверки; Chromium-диагностика не заменяет её. Откат — возврат CSS-коммита, данные не меняются.
