# Защита черновика нового клиента

Источник: следующий подтверждённый баг из аудита интерфейса от1ноября2026: «Новый клиент» терял введённые данные после Escape/X/закрытия. Пользователь поручил исправить следующий баг, ранее разрешил поставку через PR в main. Отдельной задачи Asana для этой находки в рамках исправления не создавалось.

## Критерии и решение

- Пустая форма закрывается сразу. Dirty определяется фактическими изменениями data+contacts относительно снимка при открытии; фокус и раскрытие разделов не считаются изменением. Возврат значений к исходным снимает защиту.
- Крестик, фон, Escape и Telegram Back используют один guard. При изменениях открывается подтверждение «Закрыть без сохранения?» с основным «Продолжить заполнение» и вторичным «Удалить черновик».
- Продолжение и закрытие верхнего подтверждения возвращают в исходную форму без очистки. Первоначальный фокус — на продолжении, Tab остаётся в подтверждении.
- Только явное удаление очищает локальный ввод; запрос в CRM не выполняется. Успешное сохранение закрывает напрямую; ошибка API сохраняет ввод.
- Во время POST синхронный busy-ref блокирует закрытие и повторный submit. Guard читает живой ref формы, а не запаздывающий эффект.
- При истечении сессии/очистке области оба окна и guard сбрасываются; прежняя защита ответа POST по actor/scopeGeneration сохранена. Черновик не переносится к следующему пользователю.
- Данные не записываются в localStorage/sessionStorage. Перезагрузка страницы и закрытие вкладки вне этого исправления; долговременное автосохранение не обещается.
- Защита подключена только к «Новому клиенту». Остальные редакторы сохраняют прежнее поведение.

## Этапы и проверки

Два аналитика проверили scope, поля контактов/оборудования, ошибки, ожидание POST и границы доступа. Два дизайнера согласовали взаимодействие и лично просмотрели финальные реальные снимки320×568 и390×844: PASS, кнопки и текст полностью видимы, форма остаётся контекстом под подтверждением.

Два независимых ревьюера проверили actual diff. Один обнаружил новый риск вложенных Modal: при одновременном закрытии исходное восстановление overflow могло оставить body заблокированным. Сначала воспроизведён regression, затем реализован общий счётчик блокировки; исходный overflow восстанавливается после последнего Modal независимо от порядка cleanup. Оба повторных ревью одобрены. Опциональный initialFocusRef сохраняет прежнее поведение остальных диалогов.

QA:

- npm run check: 514 серверных passed,4 штатных пропуска,7 ops passed, сборка успешна.
- 50 целевых desktop E2E passed: new-client guard, клавиатура, длинные поля, клиентские действия, employee scope, дизайн-регрессии и функциональный аудит.
- Дополнительный финальный desktop/mobile прогон:26 passed,2 штатных пропуска desktop-only на mobile. Проверены Tab, истечение сессии с двумя окнами, восстановление overflow и вход другой роли с пустой формой.
- Новые проверки: clean/dirty по всем4каналам, продолжение/повторный close/discard, нулевой POST при удалении черновика, исходный body overflow после каждого цикла, имя обратно к пустому, contact-only и equipment-only изменения,429с сохранением ввода, задержанный POST/повторный submit/блокировка закрытия, успешное сохранение и новая пустая форма.
- Существующие keyboard-navigation и long-text-fields адаптированы явным подтверждением discard нового клиента; прежние assertions сохранены.

Релиз: после финального QA — PR и полный CI, затем main. Production-данные/БД/API/роли не меняются, миграций нет. Откат — revert PR. Реальные iOS/Android устройства не использовались; Telegram Back и клавиатурная область проверены эмуляцией Chromium.
