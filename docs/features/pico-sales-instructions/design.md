# Дизайн, UX, безопасность

Общий Zod-контракт SalesUpdate расширяет activity и extraction аддитивно. JSONB records уже поддерживает хранение; новые таблицы и массовое переписывание данных не нужны. Каждая сохранённая activity — ревизия пяти блоков. Проекция собирается по company и паре проект/конечный заказчик. Если заказчик не повторён или уточнён впервые, допускается только единственное совместимое совпадение имени проекта. При нескольких кандидатах запись изолируется; её сумма не добавляется к объёму сделок. Без названия проекта — изолированная ревизия, не угадывание сделки. Привязка событий фиксируется во время построения проекции, а не пересчитывается по её конечному состоянию.

Каждое поле сделки несёт value и certainty (confirmed/assumption); null — нет обновления. Предположение не заменяет подтверждённый факт. Отрицательный confirmed-факт заменяет старое положительное значение и снимает балл. Scorer и question policy — чистые общие функции; AI не назначает баллы и не задаёт произвольные вопросы.

Server ACL остаётся в CrmService; коммерческий отчёт требует leader. История и projection читаются только из доступной компании. Все мутации через существующие version/transaction/confirm. Неперспективность и открепление — бизнес-факты, не изменение owner или archived. Вендоры блоков 2/3 ограничены направлениями; дополнительные потребности отдельно разрешают вендора. UI выводит текст React, без HTML; внешние данные не исполняются. Ключи и рабочая .env не читаются.

UX: пять блоков в карточке и превью, неизвестное «не указано», предположения явно помечены. Оценка — шесть точек с aria-label и списком недостающих фактов. История раскрывается отдельно. Вопросы показываются при превью, не мешают сохранить известные факты; «не знаю» даёт предложение уточнить на следующем контакте, без давления.

Отчёт детерминированный: сделки с обновлением в периоде occurredOn, последнее состояние каждой сделки на конец периода; результаты берутся только из событий периода. Разные категории объёма не складываются вместе. Общие суммы считаются только из подтверждённых amount. Период ограничен валидными датами, автор фильтруется UUID. Текстовый вывод не используется как HTML.

Риск: модель может ошибиться в извлечении/ certainty; пользователь проверяет черновик. Тестовые адаптеры не подтверждают качество live-модели. Откат — revert feature; старый код не знает новые JSON-поля, поэтому старые структурированные записи не редактировать старой версией. Перед выкладкой backup по README. Новые activity не удаляются при откате.
