# Требования и приёмка

Источник — source.md. Два аналитика независимо изучили код, затем согласовали решения через взаимные сообщения. Этот регламент приоритетнее прежнего ограничения одного вопроса и трактовки КП как конкурентного предложения.

1. Текст, голос Telegram и web-отчёт используют общий контракт пяти блоков: клиент, годовой потенциал, сделки, дополнительные потребности, договорённости.
2. Сервер вычисляет шесть баллов только по подтверждённым положительным фактам. Контакт принимающего решение и прямой доступ дают один совместный балл. Старые неструктурированные записи не получают выдуманную оценку.
3. Вопросы: неизвестная сумма — один; менее 1 млн — ноль; 1–5 млн включительно — дата, альтернативы, позиция предложения; более 5 млн — недостающие данные формулы, критерии выбора последними. Не более трёх на весь ответ. Без повторной автоматической порции. Отложенный ввод, явно откреплённые и неперспективные — без вопросов. Отсутствие потенциала в данных не равно нулевому потенциалу.
4. Подтверждение человеком обязательно. Новые ревизии сохраняются с датой, автором и источником, старые значения остаются. Null означает «не сообщено», не удаление. Предположения не затирают подтверждённые факты. Разные сделки не смешиваются.
5. Руководитель и администратор получают отчёт за период; менеджеру endpoint запрещён. Отчёт исключает явно откреплённых/неперспективных, разделяет объёмы, сохраняет приблизительность, не придумывает результаты, не суммирует повторные ревизии как новые сделки.
6. Mini App показывает пять блоков, шесть доступных точек, недостающие позиции и историю; черновик показывает структурированные сведения до сохранения.

Границы: без новой AI-модели, интеграций, платёжных функций и изменения прав. Нет выкладки, изменения Asana, merge или live-бота в этом задании. Неизвестные расшифровки внутренних терминов не придумываются.
