# Общий фильтр сотрудников

Запрос: согласованный дизайнером общий фильтр для руководителя/администратора с особым вниманием правам и безопасности. User подтвердил сохранить существующие права: руководитель читает/редактирует всю CRM, назначает/архивирует только внутри команды; это не меняется. Фильтр сужает выборку, не выдаёт права и не действует как impersonation.

Analyst/Product: одна выбранная персона на home/clients/projects/tasks/calendar/files/analytics/reports, выбор сохраняется при навигации/перезагрузке текущего пользователя. Профиль и управление командой/пользователями не фильтруются. Проекты пока без отдельного ответственного — явно проекты закреплённых клиентов. Компании/проекты/контакты/файлы/аналитика по текущему company.owner_id; задачи по assignee_id (включая выполненные задачи с прежним исполнителем после передачи); отчёты и коммерческий отчёт по author_id. Автор создания и текущий владелец не смешиваются. Новые записи создаются от фактического вошедшего пользователя; выбор не меняет owner/author.

UX/Designer: компактная белая панель под app header, Данные сотрудника + native select16px mobile, Все сотрудники и сброс×40px; desktop max420. Без дублирования в sidebar/системной панели Telegram. Старый фильтр Ответственный клиентов убирается. Смена выбора очищает прежние строки/открытые формы; явные loading/error/empty/reset состояния. Недоступный выбор сбрасывается после серверной проверки с уведомлением. Профиль/Team/Users сохраняют свою семантику.

Architect/Security: новый минимальный GET employee-filter/options (id/name/role), optional employeeId на существующих collection APIs. Admin выбирает любого активного сотрудника; supervisor себя/активных managers с supervisor_id=self; manager только себя (UI не показывает общий фильтр). На каждом scoped запросе resolver проверяет из БД active/role текущего actor и target/team relation; отсутствие параметра сохраняет документированное ACL. Некорректные UUID/array400, недоступный/неизвестный target403 без раскрытия существования. Параметризованный SQL и дополнительное пересечение базового ACL. Analytics audit и company выборки используют одинаковую границу. Commercial employeeId задаёт автора, конфликт authorId400. ProjectName context join привязан к той же company_id. Кешированные ответы принимаются только при совпадении actor/scope/generation; role/login/revocation очищают состояние. Миграций/новых интеграций нет. Rollback — revert commit, бизнес-данные не затрагиваются.
