# Полная проверка элементов интерфейса Pico

Основание: пользователь запросил пройти все кнопки и элементы после обнаружения растянутых значков и неверного расположения приветствия. Проверка и исправление воспроизводимых дефектов входят в задачу; публикация не входит.

Источник состояния — текущий код на ветке codex/pico-layout-regressions с предыдущими проверенными исправлениями. Посторонние .gitignore/MCP/IDE изменения сохраняются.

Критерии: составить перечень доступных пользователю действий и состояний; проверить основные и дополнительные экраны и вложенные формы на 360/390/1440 px; проверить роли manager/supervisor/admin; геометрия иконок, читаемость текста, длинные значения, отсутствие наложений/горизонтального переполнения, доступность действий и корректные переходы. Каждый дефект должен иметь воспроизведение, исправление и независимую повторную проверку. Указать непроверенные реальные интеграции честно.

Область: вход/выход/обновление/помощь; главная; клиенты и полный экран клиента; контакты/направления/заметки/файлы/письма; проекты и участники; задачи и календарь; аналитика и коммерческий отчёт; отчёты/черновики; команда и CSV; пользователи; профиль и подписи.

Архитектура и безопасность: минимальные локальные исправления по фактам аудита, серверные права сохраняются. Тестовая БД и синтетические файлы/письма; внешние Telegram/OpenAI не вызываются. Проверка отображения интеграционных состояний через явно обозначенные mocks не равна проверке live-интеграции. Production и пользовательские данные не изменяются. Откат зависит от фактического состава исправлений; для DOM/CSS — возврат локального изменения без изменения данных.

Процесс: Analyst/Product/UX — критерии выше; Architect/Security — ограничения выше; Developer — passed, подтверждённые дефекты исправлены; Reviewer — passed независимо по каждой группе фактического diff до соответствующей QA; QA1/QA2 — passed в явно указанной области; Product Owner — accepted, локальные классы действий и критерии сопоставлены с тестами/матрицей; Release — prepared, unpublished.

## Подтверждённые дефекты и исправления

- Длинное непрерывное название компании расширяло заголовок шторки; автофокус сдвигал содержимое по горизонтали. Исправлены min-width и перенос заголовка, размер кнопки закрытия сохраняется.
- После изменения собственного имени/роли интерфейс оставался со старым Actor. Refresh обновляет текущего пользователя из серверного списка; недоступная вкладка пользователей/команды возвращается на главную.
- После успешного создания письма и отказа refresh повторное нажатие могло создавать второй PDF. Сохранение подтверждается до обновления списка; форма закрывается, сбой обновления явно отличён от сбоя создания.
- Выход сохранял предыдущие карточки в памяти. При последующем входе другой роли с отказом refresh они могли появиться в интерфейсе, хотя сервер отклонял доступ. Выход очищает все данные/формы/фильтры, инвалидирует старые ответы; новый Actor показывается только после успешного refresh.
- Выход отсутствовал в доступном мобильном меню. Добавлен тот же безопасный logout.
- Дополнительное меню не закрывалось по Escape. Добавлены Escape с возвратом фокуса и закрытие при нажатии вне меню.

- В разделе «Документы» длинное название компании расширяло layout viewport с 390 до 1441 px; фиксированная навигация оказывалась вне экрана. Добавлены ограничения grid/row, перенос текста и фиксированная кнопка скачивания.

- Длинные названия в списке/раскрытом проекте расширяли страницу. Исправлены grid, переносы и кнопки проекта.
- Длинные названия компаний в «Нет контакта 14 дней» расширяли страницу «Команда». Исправлены переносы текстовых панелей/сотрудников; таблица продолжает прокручиваться внутри контейнера.
- После отключения собственного доступа сохранённый интерфейс оставался открыт. Refresh сначала проверяет текущего пользователя через `/me`; только отказ авторизации 401/403 очищает аккаунт. Транспортная ошибка 503 не отключает действующий аккаунт. Смена роли очищает прежние коллекции до загрузки новых, ограниченных сервером.
- Очень длинное выбранное имя клиента в форме участника выходило за границы кнопки. Общий PickerRow получил отдельный переносимый flex-контейнер значения и фиксированную стрелку.

Reviewer независимый: passed для каждого фактического исправления до соответствующих повторных QA-прогонов. Локальные пробелы действий закрыты; итоговые результаты приведены ниже. Матрица действий и окончательные результаты будут дополнены по завершении аудита.

## Закрытие пробелов действий

Отдельные UI-сценарии выполнили подтверждённое удаление контакта/задачи и отмену; удаление оборудования с пересчётом суммы; перемещение участника вниз и drag reorder, отмену/подтверждение удаления и сохранение порядка; редактирование существующих проекта/задачи через полный экран клиента с сохранением остальных полей; переходы к клиенту; отклонение голосового черновика с ошибкой/повтором; отказ last-admin с сохранением формы. Для seeded voice-draft и last-admin UI использованы явно обозначенные mocks; реальные серверные права и операции подтверждены серверными тестами. QA2: 10/10 дополнительных сценариев desktop/mobile, без новых дефектов.

Визуальный аудит: Chromium 12/12, WebKit 6/6 на 360/390/1440 px, CSS-масштабирование 125% 2/2; 49 отдельных состояний, 486 комбинаций снимков/браузера/ширины в `/tmp/pico-ui-audit-coverage.json`. Проверка WebKit выполняется на локальном HTTP с удалением только CSP upgrade-insecure-requests из тестового HTML-ответа, исходная политика приложения не меняется. CSS-масштабирование не равно нативному browser zoom. Дополнительные сценарии закрывают удаление направления, быстрые переносы, историю и обновление.

Проверки серверного набора: параллельный `npm run check` подвис на roles.test и был остановлен; результат не считается успешным. Повтор идентичного подхода заменён полной последовательной проверкой `node --test --test-concurrency=1 dist/tests/*.test.js`: 333 test, 331 pass, 2 штатных skipped, 0 fail/cancelled. Выбор тестов и assertions не изменены. Ops 7/7 pass. Итоговый `npm run build` passed после завершения браузерных проверок. Результат E2E приведён ниже.

Дополнительные пробелы действий закрыты: QA1 4/4 сценария desktop/mobile — удаление направления с сохранением/повторной загрузкой, переходы проекта/клиента, оба уровня истории, контекстная задача с реальным projectId, обновление и отмена onboarding, переносы на час/неделю с сохранением. QA2 10/10 дополнительных сценариев — реальные удаления/перестановки/редактирование перечислены выше. Итоговая карта содержит 494 комбинации состояний, браузеров и размеров; все локальные классы доступных действий сопоставлены с UI-сценариями, ограничения live-интеграций сохранены.

Первый общий E2E выявил устаревшую тестовую подмену CSV: Telegram ID менялся только в ответе dev-auth, хотя текущий пользователь теперь берётся из `/me`. Тест переведён на реально созданного числового пользователя изолированной БД и синтетическую тестовую сессию; проверки успеха/ошибки/скачивания не изменены. Независимый review тестовой подготовки passed; focused CSV 8/8. Это исправление тестового fixture, не приложения. Полный объединённый прогон включает 134 сценария.

## Итоговая приёмка

Два независимых тестировщика: открытых подтверждённых дефектов приложения в проверенной области нет. Все выявленные локальные пробелы доступных классов действий закрыты, включая разрушительные действия на синтетических данных. Финальные 134 уникальных E2E-сценария проверены: общий прогон 133 PASS, один отказ Chromium Page.captureScreenshot при слишком большом full-page bitmap тестовых данных; диагностические снимки ограничены viewport без изменения функциональных/геометрических assertions, повтор затронутого файла 4/4 PASS, в том числе точный упавший сценарий. Это агрегированная приёмка, не один чистый запуск 134/134. Финальные серверные тесты 331 PASS / 2 существующих PDF skips; ops 7/7, build, форматирование и diff check passed. Параллельный check не считается passed; его нестабильность и эквивалентный полный serial gate описаны выше. Причина concurrency-sensitive зависания окончательно не доказана.

Обнаруженная старым CSV-тестом подмена ID только в UI заменена реальным числовым актором изолированной БД и синтетической сессией; assertions не ослаблены. Снимки pico-style теперь viewport, чтобы не превышать лимиты Chromium на накопленном наборе fixture-данных. Source и тесты заморожены; тестовые серверы/браузеры остановлены. Production, push и live-интеграции не выполнялись. Данные/схема БД приложения не изменены; откат — возврат локальных frontend-изменений с сохранением пользовательских данных.
