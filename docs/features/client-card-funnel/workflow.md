## Требования и решения

- Серверная воронка аналитики: 0 Новый, 1–2 Знакомство, 3–5 Развитие, 6–7 Партнёр, 8 Наш клиент. Не использовать ручную стадию сделки или шкалу из 6 баллов. Сегменты 1:2:3:2:1, реальные баллы из 8.
- Пять независимых accordion: Потенциал, Контакты, Файлы, Заметки, Данные. Суммы оборудования редактируются в миллионах с пересчётом сохранённого итога; ноль допустим, отрицательное/нечисловое значение запрещено.
- Компактные контакты: ФИО, Должность | Телефон, E-mail; файлы с типом/датой; заметки без добавления источников; данные ИНН, название, город, категория, сайт.
- Swipe двигает всю ячейку; клиент/контакт — правка и корзина; оборудование/файл — корзина. Вертикальный scroll сохраняется; жест только раскрывает действия. Доступен клавиатурный путь. Иконки раскрытого клиента центрируются по видимой части.
- Правка клиента и контакта в opt-in bottom sheet с сохранением доступности Modal, ошибок и черновика.
- Пользователь подтвердил корзину клиента как архивирование с восстановлением. Использовать существующий endpoint и серверные ограничения; роли не расширять. Восстановление — существующая карточка архива для администратора.
- API optimistic version сохраняется; конфликт/сбой не должен затирать черновик. Сайт — сохраняемое поле с безопасным HTTP(S) URL. Существующие записи получают пустой default без изменения бизнес-данных.

## Scope, архитектура и безопасность

Обычная UI feature с изменением контракта detail и добавлением optional/default поля в JSON. Серверный score из общей функции и текущих настроек, включая проектные связи и provenance контактов; не дублировать формулу в UI. ACL остаётся серверным источником правды. Изменения локализовать в ClientRow, переиспользуемом swipe, opt-in форме и стилях; не менять несвязанные правки пользователя. Никаких live API мутаций, production, merge или релиза. Сайт отображать текстом либо проверенным HTTP(S) URL. Полное удаление клиента не вводится.

Откат: revert только feature diff; JSON website допускает отсутствие, данные не удалять. Миграция таблиц не нужна. Перед внешним выпуском проверить совместимость старой строгой схемы с новым ключом website; при откате старого сервера сохранить backup и обновить его схему чтения либо оставить совместимую схему.

## Проверяемая приёмка

Реальный server score и все пороги; независимое раскрытие разделов; сохранение и повторное чтение сумм/контактов/сайта/заметок; отклонённое сохранение сохраняет черновик; swipe/cancel/keyboard и вертикальная прокрутка; archive ACL и сохранение связей; рендер 390×844 и широкого экрана с длинными строками, без overflow, focus/BackButton и доступной кнопкой сохранения.
