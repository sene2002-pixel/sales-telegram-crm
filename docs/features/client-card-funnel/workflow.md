# Карточка клиента: интеграция с актуальным main

Источник: Asana https://app.asana.com/1/1218599458205876/project/1218585786925552/task/1219626327457928. Полное описание, подзадачи, вложения и комментарии прочитаны в Chrome 24.10.2026: отдельных вложений/подзадач и пользовательских комментариев не было. Прочитаны все страницы спецификаций Google Docs «Карточка клиента» (19.10) и «Новый клиент» (18.10), документ аналитики и список общей папки. Claude-макет недоступен и явно исключён пользователем. Корзину клиента пользователь согласовал как архивирование с восстановлением.

## Требования и критерии

Пять этапов клиентской воронки из аналитики и баллы из 8; разделы Потенциал → Контакты → Файлы → Заметки → Данные; редактирование сумм в миллионах с пересчётом; компактные контакты; свайп всей ячейки с правкой/корзиной клиента и контакта и корзиной оборудования/файла; формы правки снизу. При отказах и конфликтах черновик сохраняется, чужие изменения не затираются. ACL и архивирование остаются серверными. Заголовок, закрытие и сохранение доступны на телефоне, широком экране и при уменьшении рабочей области Telegram.

## Интеграция

По запросу пользователя перед выпуском получен актуальный origin/main e4b2681. Первоначальная рабочая ветка была на e2e5f6b; изолированная ветка codex/client-card-main-integration сохраняет исходный feature commit и слияние актуального main. Несвязанные незавершённые изменения в исходной папке не переносились и не менялись.

Main уже содержал карточку, новые холдинги, атомарный `/companies/:id/editor`, версии контактов, актуальную аналитику и более строгую проверку сайта. Поэтому они сохранены как единая реализация. Старые дублирующие компоненты и серверный clientScore из первоначального feature не заменяют новые возможности main. OpenAPI остаётся доступным по запросу по правилам актуального main, производный JSON обратно не добавлялся.

Итоговый diff относительно main:

- `InlineValue` фиксирует callback сохранения при начале ввода, сохраняя исходные данные и version при фоновом refresh. Повтор после 409 не подменяет версию автоматически. Правило применяется к заметкам, суммам и полям клиента.
- Добавление оборудования хранит снимок компании/версии с открытия формы.
- `Modal` имеет opt-in sheet для правки карточки и контакта. Ручка и заголовок отделены от прокрутки; внутренний scroll и footer актуальной CompanyForm сохранены; максимальная высота учитывает `--pico-view-height` и safe-area. Остальные модальные окна не меняются.
- Тесты воспроизводят настоящие конкурентные PATCH, два отклонённых сохранения, неизменность серверных данных и сохранность черновика, отказ 429 и повтор контакта, закреплённую шапку и сохранение при уменьшенном Telegram viewport. Старый mock inline-редактора приведён к серверному контракту версий: повторный stale PATCH возвращает 409; успешное сохранение требует Cancel и явного переоткрытия с актуальной версией.

## Этапы и свидетельства

Два аналитика и два дизайнера выполнили первоначальный анализ/дизайн. При интеграции выполнен дополнительный анализ различий с main. Два независимых reviewer проверили фактический diff относительно origin/main и исправления; вердикты approved. Reviewer 1 выявил потерю ограничения Telegram viewport из-за нового wrapper: исправлены safe-area/max-height и вложенный flex формы; повторное ревью passed. Reviewer 2 отдельно подтвердил, что проверка 409 усилена, а не ослаблена.

Первоначальная отдельная реализация прошла 410 серверных тестов (4 предусмотренных skip), 7 ops и 72 браузерные проверки. Эти числа относятся к старой базе и не подменяют проверку интеграции с новым main.

Локальные проверки интеграции: `LETTER_PYTHON=<изолированный Python с ReportLab> npm run check` — 518/518 серверных тестов, 0 пропусков, ops 7/7 и обе сборки PASS. Адресные Playwright client-card/actions/inline/editor-concurrency/company-form-backlog — 29 PASS и 1 предусмотренный skip mobile landscape. Включена имитация уменьшенного Telegram viewport (460px с safe-area) при неизменном layout viewport. Два независимых дизайнера проверили четыре итоговых screenshot — PASS. Форматирование изменённых файлов и diff whitespace — PASS. Полный GitHub CI финального head остаётся обязательным до слияния. Первое локальное check выявило отсутствие ReportLab в прежнем окружении; подготовлен изолированный Python в /tmp. Первые 2 падения старого inline mock выявили ожидание автоматической замены версии после 409; исправлен mock и добавлены строгие проверки сохранности ввода и данных.

## Выпуск и откат

Пользователь разрешил публикацию в main после получения актуального main. Изменения публикуются через PR согласно AGENTS.md; обязательные CI должны пройти на финальном head. Production deployment и изменения Asana не выполняются этим выпуском. Новых миграций/серверных контрактов относительно main нет; откат — revert итогового PR, без удаления клиентских данных. Исходная рабочая папка с чужими незавершёнными изменениями остаётся нетронутой.
