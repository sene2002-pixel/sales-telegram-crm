## Решения и критерии

- Аналитика/продукт: два аналитика сопоставляют реальные дефекты с первоисточниками. Не считать успешную сборку доказательством полного соответствия четырём задачам.
- UX/дизайн: корзина скрыта до намеренного свайпа влево, жест сам не удаляет; обратный жест закрывает действия. Редактирование компании и контактов сохраняет ввод при ошибке/конфликте; удаление не следует из отсутствия контакта в payload.
- Архитектура: атомарный editor; версии компании и каждого существующего контакта; согласованный порядок блокировок hierarchy → actor → company.
- Безопасность: повторная проверка действующего пользователя после блокировки; нельзя передать чужой контакт, перенести ответственность через файл или раскрыть чужие совпадения импорта.
- Идентичность: разные валидные ИНН не объединяются по названию; нечёткое распознавание не переименовывает посторонние юрлица. Явный тип подрядчика/интегратора не превращается в заказчика холдинга.
- Целостность: контактные extension/provenance сохраняются; предпросмотр отчёта руководителя ищет карточки владельца отчёта; подтверждённые референсы одного холдинга не повторяются.
- Импорт: сохранённые данные не затираются пустотами; повтор файла идемпотентен; объединение проектов подтверждается; журнал позволяет безопасный ограниченный undo. ODS сохраняет позиции объединённых ячеек и разделение контактов, не импортирует скрытые листы. Секретные колонки удаляются до сохранения raw, архивы/формулы ограничены.

## Повторная диагностика и корректировки

Два независимых ревью закрыли ошибки слияния разных ИНН, принадлежности холдингу по подстроке, потери extension, отозванных ролей, выбора карточки руководителя вместо автора отчёта, порядка блокировок, повторов референсов и явного типа клиента. Для импорта воспроизведены и исправлены архивирование ранее существовавшей карточки при undo, незапланированные холдинги после реестрового обогащения, смешение стран, параллельные предпросмотры одного файла, потеря второго телефона и псевдонимов.

После двух корректировок географии подход пересмотрен: отдельные проверки имени заменены единым пулом идентичности. Пул сопоставляет только предварительно проверенные факты: страну, организационную форму, ИНН и адресованные поля города. Дополнение неизвестного ИНН обновляет этот же пул; иностранный российский ИНН исключается до сопоставления. Разные явные реквизиты не объединяются.

У общего набора наблюдались непостоянные HTTP 403/405/ECONNRESET в разных несвязанных тестах при 14 одновременно запускаемых файлах. Изолированные проверки и один полный прогон проходили. Причина не объявляется доказанной; тестовые файлы теперь ограничены двумя одновременно (как на обычном CI runner), assertions и конкурентные бизнес-сценарии сохранены. Изменение конфигурации отдельно проверено reviewer 1. Диагностические hooks находились только в /tmp и в репозиторий не включаются.

## Остатки и ограничения

Реализованы произвольные явно размеченные таблицы проектов, контактные продолжения, явная иерархия 1С, легенды и списки договоров. Не поддерживается реестровый поиск по названию/городу/обрезанному префиксу без ИНН. Существующий адаптер поддерживает только запрос по валидному ИНН; без отдельного рабочего контракта провайдера нельзя обещать восполнение таких реквизитов.

Фото/OCR отложены пользователем. Живые Google/Saby/Telegram, production и нативная конкуренция PostgreSQL не проверены локальным PGlite-набором. Полное закрытие задачи нормализации не подтверждено; её оставлять In Progress. Визуальный Claude-артефакт по-прежнему требует доступа.
