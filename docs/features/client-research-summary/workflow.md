# Выжимка исследования в заметках клиента

Проблема: бот создавал заметку «Источники проверки» с URL, которую нельзя использовать как сведения о клиенте. Пользователь уточнил: нужны факты со страниц, а не ссылки или их оформление.

Решение: результат существующего веб-поиска включает summary — до 1200 символов русской выжимки. Деятельность, продукция, география и особенности берутся только из доступных источников; гипотезы о потребностях и перенос фактов холдинга на юрлицо запрещены. При недостатке сведений текст короче или пустой. Сводка показывается перед подтверждением компании и сохраняется в notes новой карточки. sources остаются в исследовании для проверки. URL в summary отклоняются валидатором.

Область: новые карточки из поиска компании для письма. Старые задания без summary используют уже известную деятельность; существующие пользовательские заметки и production-данные не перезаписываются. Старые URL нельзя превратить в факты без повторного исследования страниц.

Критерии: сводка сохраняется вместо URL; источники остаются доступны внутренней проверке; длинный текст и URL не принимаются; пользователь видит сводку до подтверждения. Изменений UI, БД и прав нет.

Ревью: самостоятельная проверка diff; схема строгого ответа содержит обязательное summary, старое сохранённое исследование нормализуется отдельно. Ограниченный размер укладывается в сообщение предпросмотра. Проверка ссылок источников и подтверждение компании сохранены.

Проверки: npm run check — успешно: 514 тестов прошли, 4 пропущены; ops-проверки и сборка прошли. Интеграционные тесты проверяют сохранённый notes и внутренние sources; негативный тест — URL и превышение длины. Реальный внешний AI-поиск не выполнялся, качество фактической выжимки требует проверки на живом примере после выкладки.

Откат: отменить коммит; миграций нет. Уже созданные текстовые заметки остаются обычными заметками.
