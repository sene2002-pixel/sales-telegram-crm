# Закрытые клиенты и фильтры

Источник: Asana [закрытые клиенты](https://app.asana.com/1/1218599458205876/project/1218585786925552/task/1219858679188223) и [удаление архивного фильтра](https://app.asana.com/1/1218599458205876/project/1218585786925552/task/1219855149975703). Обе задачи прочитаны полностью через браузер: отдельных вложений, подзадач и комментариев нет; связанная папка содержит общие спецификации. Ссылка Claude возвращает «Страница не найдена», поэтому визуальное сравнение с исходным холстом недоступно.

## Требования и решение

- «Закрытые» показывает `archived || stage === 'closed'`; «Все» и «В работе» исключают оба состояния.
- Старые архивные записи появляются сразу, без миграции или изменения данных. Корзина сохраняет существующий API архивирования, связанные записи и проверки версии/прав.
- Главный счётчик исключает архив и закрытую стадию.
- Удалён архивный переключатель. Сортировка слева, сброс справа одной строкой; остальные фильтры сохранены.
- В раскрытой архивной карточке администратору доступна заметная кнопка восстановления, открывающая существующие действия с подтверждением. Неработающий редактор архивной компании через свайп скрыт. Руководитель и менеджер не получают дополнительных прав.

Выбран прямо разрешённый описанием минимальный вариант: исправить отображение закрытых. Новые свайп возврата, уведомление с отменой и безвозвратное удаление не входят в поставку. Пользователь ранее выбрал архивирование с возможностью восстановления. Существующее восстановление снимает архивный флаг, сохраняя бизнес-стадию; если она `closed`, компания остаётся в «Закрытых», пока стадию явно не изменят. Это не миграция стадий и не удаление данных.

## Этапы

- Анализ: два аналитика независимо подтвердили причину в предикате списка и отсутствие необходимости миграции. План принят.
- UX/дизайн: два дизайнера согласовали минимальный вариант; оба проверили шесть реальных снимков 320/390 px. Строка фильтров принята; по их замечанию снимки вкладки пересняты после анимации, а кнопки восстановления — с прокруткой над нижней навигацией. Повторная визуальная приёмка ожидается.
- Разработка: изолированная feature-ветка от актуального `origin/main` (`99b18bb`), исходный checkout с пользовательскими изменениями сохранён.
- Архитектура/безопасность: API, ACL, транзакции, защита версии и правила холдингов сохранены. Данные производства не изменялись.
- Ревью: два независимых ревьюера проверили фактический diff, блокеров нет. Замечание к точности проверки счётчика исправлено.
- QA: `npm run check` — 514 серверных тестов прошли, 4 штатных пропуска PostgreSQL/PDF, 7 ops-тестов прошли, сборка успешна. Новый сценарий архив → Закрытые → восстановление → В работе с сохранением контакта прошёл на 320/390 px в desktop/mobile Chromium (4 теста). Проверка фильтров проверяет геометрию, сортировку и сброс. При первом запуске обнаружено смещение на 5px из-за margin поля; исправлено, повторная проверка прошла.
- QA интеграции: 32 целевых E2E прошли (закрытие/фильтры, существующие роли и функции, свайпы) на desktop/mobile. Дополнительный прогон новых четырёх сценариев после уточнения снимков успешен.
- Приёмка/релиз: ожидают финальной проверки дизайна и CI; затем merge и обновление обеих Asana задач.

Откат: revert единственного коммита PR. Миграций нет, архив и связанные записи остаются доступны через API. Проверка в Chromium не заменяет испытание физических iOS/Android устройств.
