# Полноэкранное открытие и адаптивный viewport

Запрос: отключить pinch zoom, открывать приложение на весь экран, автоматически адаптировать интерфейс. Обычная frontend-функция; ветка codex/pico-fullscreen-viewport, исходный a45fc9b. Посторонние MCP/IDE/.gitignore изменения сохраняются.

Analyst/Product/UX: при запуске SDK ready/expand, requestFullscreen при поддержке8.0; старые версии/отказ продолжают expanded/browser работу. Учитываются вырез/системные области и отдельная content-safe-area Telegram. Позднее пользователь уточнил: только вертикальная ориентация. Telegram8 фиксирует текущий режим, поэтому native lock вызывается только в portrait; заранее заблокированный landscape освобождается. ScreenOrientation.lock(portrait) — best effort. Если мобильный клиент не позволяет принудительный поворот, горизонтальный интерфейс скрыт за просьбой повернуть устройство; в portrait native lock удерживает положение. Физическая ориентация отделена от уменьшения viewport клавиатурой. Desktop остаётся адаптивным; клавиатура уменьшает видимую область, модальные формы остаются прокручиваемыми. Блокируется pinch, одиночный вертикальный/горизонтальный скролл сохраняется. Запрос отключения zoom явный; ОС/браузер могут иметь собственные средства увеличения.

Architect/Security: отдельный configureViewport модуль, ограниченные CSS-переменные; изменения viewport/safe-area/fullscreen и visualViewport; cleanup всех обработчиков. Native SDK ошибки не прерывают auth. Стабильная высота Telegram для layout, меньшая visualViewport height для клавиатуры. Device safe inset и content inset суммируются, device inset не дублируется с CSS env. Без серверных изменений/миграций/интеграционных вызовов.

Developer: реализовано; Reviewer выявил и исправлены повторные попытки неподдерживаемого lock, предварительно заблокированный landscape и версия поддержки RGB header color6.9. Независимая повторная review passed до финальной QA; оба тестировщика завершили проверки. Источник SDK: https://core.telegram.org/bots/webapps#initializing-mini-apps. Native fullscreen зависит от Telegram8.0/платформы; тестовые SDK-события не равны проверке физического клиента. Откат — возврат HTML/JS/CSS без изменения данных. Пользователь позднее явно разрешил пуш в main вместе с сокращением названий компаний.
