# Приглашения в команду

## Требования и решения

Пользователь подтвердил приглашение руководителем сотрудника в свою команду через Telegram. Это отдельное разрешение создать manager, существующее администраторское управление ролями остаётся прежним. Руководитель создаёт/читает/отзывает только собственные приглашения своей команды; администратор выбирает активного руководителя. Одноразовая ссылка действует24часа, может быть отозвана. Только новый Telegram-пользователь присоединяется; действующие/заблокированные пользователи не меняются. Повторная доставка тому же получателю безопасна. Username берётся у текущего бота, ngrok не влияет на ссылку.

## Архитектура и безопасность

Случайный32байт токен, в БД только SHA256. Атомарное погашение под блокировкой управления пользователями и строки приглашения. Проверка актуальной роли/активности отправителя и руководителя. Токен не включается в audit, diagnostics, AI; ссылка выдаётся только при создании и хранится в UI в памяти. Получатель подтверждён private update Telegram с webhook secret. Приглашение является bearer-доступом: предупреждение передавать лично, срок и отзыв ограничивают риск пересылки.

## Развёртывание и откат

Повторяемая additive-миграция отдельной таблицы. Перед обновлением обычная резервная копия PostgreSQL; старый код игнорирует таблицу. Откат приложения отключает создание и погашение ссылок; таблицу/audit сохраняем, данные пользователей не удаляем. Не выполнены production-операции.

Telegram deep-link contract verified against https://core.telegram.org/bots/features#deep-linking : invite_ +43base64url characters fits64-character start limit.
