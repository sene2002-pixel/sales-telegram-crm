# Информационные письма ESQ

В карточке компании нажмите «Создать письмо». Без контактов под кнопкой появляется ошибка. Один контакт выбран автоматически; при нескольких нужно выбрать адресата. Должность контактного лица должна быть заполнена в CRM. Данные CRM автоматически не изменяются.

В разделе «Мой профиль» → «Подпись для писем» загрузите визитку JPEG/PNG до 10 МБ. Проверьте распознанные поля в редактируемой форме и нажмите «Сохранить изменения». Можно заполнить форму вручную. Подпись хранится отдельно для каждого сотрудника; распознавание само по себе ничего не сохраняет. Изображение обрабатывает OpenAI, исходное фото не сохраняется на диске приложения. Настройка доступна независимо от компаний и контактов. В форме письма подпись показывается только для просмотра, без перехода к редактированию.

«Сформировать PDF и сохранить» создаёт письмо в разделе «Файлы». Получатель берётся из выбранного контакта. Интернет-поиск проверяет компанию и определяет отрасль; референсы берутся из `assets/esq/REFERENCES_ESQ.md`. Генератор и оформление из предоставленного архива сохранены без изменений. При переполнении страницы абзац сокращается, число попыток ограничено. Исходящие номера 1000–9999 не повторяются для сотрудника; неудачные попытки также расходуют номера.

## Развёртывание

Docker-образ включает Python, ReportLab и шаблон. После обновления пересоберите образ: `docker compose up -d --build`. Таблицы подписей и номеров создаются при старте без изменения существующих данных.

Локально установите ReportLab в Python-окружение и задайте `LETTER_PYTHON` путём к его исполняемому файлу. По умолчанию используется `python3`. Запускайте сервер из корня проекта.

Нужен `OPENAI_API_KEY`. `LETTER_MODEL` по умолчанию `gpt-4.1-mini`; модель должна поддерживать изображения, Structured Outputs и web search. Реальные запросы распознавания и поиска платные. Автотесты подменяют ИИ и не обращаются к внешним сервисам.
