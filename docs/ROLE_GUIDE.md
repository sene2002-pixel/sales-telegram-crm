# Руководство по ролям CRM «Контакт»

## Как сотруднику узнать Telegram ID

В Telegram Desktop или на телефоне откройте личный чат работающего CRM-бота и отправьте `/myid`. Бот покажет только ваш собственный ID. Передайте его администратору для добавления в «Команда» → «Доступ сотрудников». Команда доступна без регистрации и заблокированным пользователям, но не выдаёт и не восстанавливает доступ к CRM. В группах бот на неё не отвечает. Не публикуйте ID без необходимости.

Это инструкция по текущей версии, а не список будущих планов. Краткая версия доступна внутри приложения по кнопке **«Права и помощь»** вверху экрана. Проверки каждого функционального пункта перечислены в [матрице тестов](TEST_MATRIX.md).

## Чем отличаются роли

**Менеджер** ведёт свои компании и отправляет отчёты о работе. **Руководитель** видит всю команду, может редактировать общую CRM, обрабатывать отчёты сотрудников и передавать компании. **Администратор** умеет всё то же самое, что руководитель, и дополнительно управляет пользователями и их доступом. Руководитель не является пользователем «только для чтения».

| Действие                                                             | Менеджер                                   | Руководитель              | Администратор                |
| -------------------------------------------------------------------- | ------------------------------------------ | ------------------------- | ---------------------------- |
| Создать компанию                                                     | Да; первоначально назначается на создателя | Да; затем можно передать  | Да; затем можно передать     |
| Смотреть/редактировать компанию, архивировать/восстанавливать        | Только закреплённые                        | Все                       | Все                          |
| Контакты, проекты, задачи, история и файлы                           | В закреплённых компаниях                   | Во всех компаниях         | Во всех компаниях            |
| Смотреть список сотрудников                                          | Только собственный профиль                 | Все сотрудники            | Все сотрудники               |
| Читать/править/подтверждать/отменять/повторять отчёт                 | Только собственный, с учётом состояния     | Любой, с учётом состояния | Любой, с учётом состояния    |
| Передать компанию                                                    | Нет                                        | Да                        | Да                           |
| Команда, период, показатели, CSV                                     | Нет                                        | Да                        | Да                           |
| Добавить пользователя                                                | Нет                                        | Нет                       | Да                           |
| Изменить имя/роль, заблокировать/разблокировать                      | Нет                                        | Нет                       | Да                           |
| Изменить ключи ИИ, настроить webhook, сделать backup через интерфейс | Нет                                        | Нет                       | Нет; это операции на сервере |
| Удалить компанию навсегда или стереть историю                        | Нет                                        | Нет                       | Нет                          |

«Своя компания» означает **текущего ответственного**, а не человека, когда-то создавшего запись. Собственный отчёт остаётся у автора после передачи компании, но менеджер больше не может применить его к уже чужой компании. Руководитель и администратор могут обработать такой отчёт. Скрытые кнопки дополняют серверную проверку прав, но не заменяют её.

## Первый вход и выдача доступа

В реальном Telegram обычный пользователь не регистрируется самостоятельно. Специалист, разворачивающий сервер, указывает числовой Telegram ID первого администратора в `BOOTSTRAP_ADMIN_TELEGRAM_ID`. Его первый вход через бота или Mini App создаёт администратора. Повторный вход не повышает роль и не разблокирует уже существующую запись.

Остальных пользователей добавляет администратор. Вход доступен только активным сотрудникам. Сервер проверяет подпись Telegram и срок данных входа, затем выдаёт сессию на восемь часов. После истечения сессии откройте Mini App заново. Блокировка и изменение роли учитываются при следующем запросе к серверу; уже показанная страница может оставаться на экране до обновления.

Кнопки выбора роли на стартовой странице — **локальная демонстрация**, доступная при DEV_AUTH в разработке. В production их нет. Это не способ самостоятельно стать администратором в рабочей CRM.

## Администратор: пошаговые сценарии

### Добавить сотрудника

1. Откройте **«Команда»** в меню (на телефоне меню прокручивается по горизонтали).
2. Прокрутите до **«Доступ сотрудников»**.
3. Введите числовой **Telegram ID** сотрудника, например `123456789`. Номер телефона и `@username` не подходят.
4. Введите отображаемое имя и выберите **Менеджер**, **Руководитель** или **Администратор**.
5. Оставьте флажок **«Доступ активен»** включённым.
6. Нажмите **«Создать сотрудника»**. Сотрудник появится в списке и сможет открыть `/crm` в боте. Пустая форма открывается кнопкой «Добавить сотрудника», не выбором существующей записи.
7. Назначьте ему компании через карточки. Новому менеджеру чужая база автоматически не открывается.

### Изменить роль или имя

Откройте «Команда» → «Все сотрудники» → «Редактировать» у нужного человека. Измените имя/роль и нажмите «Сохранить изменения». Telegram ID заблокирован для редактирования. «Отмена» закрывает форму без сохранения. «Добавить сотрудника» всегда открывает пустую форму; существующий ID в ней отклоняется. Кнопка «Все сотрудники» доступна руководителю и администратору; руководитель просматривает список без кнопок изменения доступа. Текущий пользователь отмечен «Вы».

### Заблокировать и вернуть доступ

Нажмите сотрудника, снимите «Доступ активен» и сохраните. Существующая сессия перестанет давать доступ при следующем обращении к серверу. Повторное включение флажка возвращает доступ. Данные человека не удаляются, компании автоматически никому не передаются. Рекомендуемый порядок при уходе сотрудника: передать его компании → проверить открытые задачи → заблокировать доступ.

### Защита последнего администратора

Система не разрешит заблокировать или понизить последнего активного администратора. Сначала назначьте другого активного администратора. Если их несколько, собственную роль можно понизить; последующие запросы уже выполняются с новыми правами.

### Что администратор контролирует

Помимо доступа, администратор может работать со всеми компаниями, назначать ответственных, исправлять контакты/проекты/задачи, добавлять историю, скачивать и архивировать файлы, проверять и подтверждать отчёты всех сотрудников, смотреть командную сводку и выгружать CSV. Для этого используются те же экраны, что и у руководителя.

## Руководитель: контроль команды

### Посмотреть результат работы

Откройте **«Команда»**. Период сводки и CSV — с начала текущего месяца по сегодня, без ручных полей «С» и «По». Ниже под «периодом» имеется в виду именно этот интервал. Строка каждого сотрудника показывает:

| Показатель           | Как считается                                                                                                 |
| -------------------- | ------------------------------------------------------------------------------------------------------------- |
| Компании             | Неархивные компании, закреплённые за сотрудником сейчас                                                       |
| Открыто              | Текущие невыполненные задачи сотрудника, независимо от выбранного периода                                     |
| Просрочено           | Невыполненные задачи со сроком раньше сегодняшнего дня                                                        |
| Выполнено            | Задачи с фактической датой завершения в выбранном периоде                                                     |
| Контакты             | Число записей о взаимодействиях за период, по автору встречи; **не** число телефонных контактов в справочнике |
| Нет контакта 14 дней | Активные компании без недавней записи в истории общения                                                       |

Дата создания карточки не заменяет встречу. Нажатие «Выполнить» фиксирует время завершения; «Вернуть» снова открывает задачу и очищает дату завершения. Неархивность компании влияет на счётчик компаний; существующие задачи архивной компании всё ещё видны в списке задач.

Нажмите **«Экспорт CSV»**, чтобы скачать текущую сводку с начала месяца по сегодня. Файл доступен также администратору; менеджеру сервер откажет в выгрузке. API сохраняет поддержку произвольного периода для интеграций.

Если скачивание внутри Telegram не сработало, нажмите **«Получить CSV в боте»**: документ придёт вам в личный чат. [Формат отчёта, настройка и ограничения](CSV_EXPORT.md).

### Найти компании сотрудника и передать клиента

1. Откройте **«База»**, выберите сотрудника в фильтре ответственного.
2. Откройте компанию. На карточке видно имя текущего ответственного.
3. В поле **«Передать компанию»** выберите активного сотрудника и нажмите **«Назначить»**.
4. Компания и её **открытые** задачи перейдут ему. Предыдущий менеджер потеряет доступ к карточке и связанным записям.
5. Авторы встреч и исполнители **выполненных** задач останутся прежними. Во вкладке **«Изменения»** появится, кто и кому передал компанию.

Передать компанию заблокированному пользователю нельзя. Если карточку успел изменить другой человек, система попросит обновить её; устаревшая форма не затрёт новые данные.

### Обработать отчёт сотрудника

В **«Отчёты»** руководитель видит все отчёты. Откройте черновик, проверьте компанию, текст, суммы и сроки, при необходимости исправьте. Подтверждение руководителем сохраняет первоначального автора встречи, а того, кто подтвердил, фиксирует в аудите. Отчёт заблокированного автора применить нельзя; сначала разберитесь с доступом автора.

## Менеджер: ежедневная работа

### Компании и поиск

**«База» → «+ Компания»**: заполните название, ИНН (при наличии), город, отрасль, сегмент, стадию, оборот, потенциал, направления и заметки. Все суммы вводятся **в рублях**. Нажмите «Сохранить компанию». Новая компания назначится на вас.

Поиск находит название и ИНН. Фильтры сужают базу по городу, сегменту и направлению. Кнопка **«Архив»** переключает список архивных компаний. ИНН проверяется по контрольной сумме и должен быть уникальным; одинаковое название само по себе не объединяет компании. Внешнее автоматическое заполнение реквизитов по ИНН пока не подключено.

Для изменения откройте карточку → **«Редактировать компанию»**. Для архивации включите «В архиве», для восстановления снимите флажок и сохраните. В архивную компанию нельзя добавлять новые контакты, проекты, встречи, задачи и файлы, а также применять голосовой отчёт. Существующие контакты/проекты/задачи можно редактировать, файлы — скачивать и архивировать.

### Контакты, проекты, задачи

- **Карточка → Контакты → + Добавить**: имя, должность, телефон, email. «Изменить» редактирует запись.
- **Карточка → Проекты → + Добавить**: название, сумма, срок, стадия, описание. Проект принадлежит конкретной компании; его видно также в общем разделе «Проекты».
- **Карточка → Задачи → + Добавить**: текст, срок и необязательный проект той же компании. Исполнитель — текущий ответственный компании. Существующую задачу можно отредактировать, выполнить или вернуть в работу.
- **Меню → Задачи**: открытые, просроченные, выполненные. Нажатие текста открывает компанию.
- **Меню → Календарь**: выберите месяц и день; увидите задачи на эту дату. Задачи без срока перечислены отдельно. Календарь не создаёт напоминания в Telegram автоматически.

### История встречи

**Карточка → История → + Добавить**: введите итог встречи и дату. Система сохранит автора. Каждая встреча — отдельная запись; старую историю нельзя редактировать через API или UI. Для уточнения добавьте новую запись. Общие заметки компании редактируются отдельно и не заменяют хронологию встреч.

### Файлы

**Карточка → Файлы**: выберите категорию, при необходимости проект и файл до **10 МБ**. Для скачивания нажмите «Скачать». Общий раздел «Файлы» показывает документы доступных компаний. «В архив» скрывает вложение из списков и закрывает скачивание, но физический файл сохраняется. Кнопки восстановления архивированного файла сейчас нет.

## Голосовой и текстовый отчёт — все роли

В личном чате бота доступны `/start` и `/help` (инструкция), `/crm` (кнопка приложения), `/tasks` (до 15 открытых задач в доступных компаниях). Групповые сообщения не обрабатываются как CRM-отчёты.

Пример диктовки: «Встретился с Иваном из Электростроя. Обсудили оборудование 0,4 кВ, потенциал три миллиона рублей. Завтра отправить предложение». Произнесите название компании, участников, результат, следующий шаг и срок. Голосовое ограничено десятью минутами и 20 000 000 байт по умолчанию. Текст можно также отправить через **«Отчёты»** в Mini App.

| Состояние        | Что происходит и что можно сделать                                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| В очереди        | Сообщение сохранено, ждёт обработки; можно отменить                                                                                        |
| Обрабатывается   | Идёт транскрипция/разбор; дождитесь завершения, отмена не предусмотрена                                                                    |
| На подтверждении | Проверьте и исправьте поля; «Сохранить черновик» сохраняет только черновик; «Подтвердить и сохранить» применяет CRM-записи; можно отменить |
| Сохранён         | Повторное подтверждение не создаёт дублей; повторное редактирование/отмена отчёта не предусмотрены                                         |
| Ошибка           | Видна причина; можно повторить обработку или отменить                                                                                      |
| Отменён          | Отчёт сохраняется для просмотра; повторное применение не предусмотрено, отправьте новый отчёт                                              |

После подтверждения итог встречи появится в **«История» компании**, люди — в **«Контакты»**, договорённые шаги — в **«Задачи»** и календаре при наличии срока. Стадия, потенциал и направления обновляются, если указаны в подтверждённом блоке. Полная транскрипция и черновик остаются в «Отчёты». Аудио физически не архивируется CRM; сохраняется его Telegram file ID.

Несколько компаний в диктовке дают несколько блоков. При совпадении имён выберите компанию явно. Если организации нет, подтвердите создание новой. Все блоки сохраняются одной транзакцией: при ошибке одного не применится ни один. Повтор webhook, повтор подтверждения и старая кнопка после изменения черновика защищены от дублей и скрытого применения обновлённых данных.

ИИ может ошибиться в названии, сумме или дате — проверьте результат. Модели по умолчанию: `gpt-4o-mini-transcribe` для речи и `gpt-4o-mini` для разбора. Ключ задаётся в серверном `.env`, поле `OPENAI_API_KEY`. Отсутствие ключа не мешает ручному ведению CRM, но автоматический отчёт завершится ошибкой конфигурации.

## Частые ситуации

- **Не вижу «Команда».** Ваша роль — менеджер; откройте «Права и помощь», чтобы проверить. Для повышения нужен администратор.
- **В «Команда» нет управления доступом.** Вы руководитель, а не администратор. В локальной демонстрации выйдите и выберите «Администратор»; в Telegram роль выдаётся сервером.
- **Новый менеджер видит пустую базу.** Сначала назначьте ему компании или попросите создать свои.
- **Компания исчезла.** Проверьте архив/фильтры; руководитель мог передать её другому сотруднику.
- **«Карточка изменена».** Закройте и заново откройте карточку; проверьте актуальные данные и повторите изменение.
- **Не вижу старый отчёт/аудит.** Сейчас список отчётов ограничен последними 200 записями, история изменений карточки — 100 событиями. Это ограничение выдачи, а не удаление из БД.
- **Хочу настроить токены или backup из админки.** Такого экрана нет. Используйте [инструкцию эксплуатации](OPERATIONS.md); эти операции выполняются на сервере.

## Что означают тесты

Автотесты проверяют правила доступа, сохранение данных, обработку ошибок и поведение интерфейса. Тестовые адаптеры ИИ не доказывают качество распознавания живой речи. Реальный Telegram/OpenAI, HTTPS, нативные iOS/Android и восстановление резервной копии требуют отдельной приёмки по [OPERATIONS.md](OPERATIONS.md). Матрица не помечает эти проверки как выполненные автоматически.
