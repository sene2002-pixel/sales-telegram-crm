## Требования, для которых запрошено уточнение

### Приоритет регламентов

[Инструкции для бота Pico: вопросы, отчёты, разбивка для CRM](https://app.asana.com/1/1218599458205876/project/1218585786925552/task/1218735864996771) содержат новый регламент:

- Вопросы по размеру сделки: сумма неизвестна — уточнить; до 1 млн — без вопросов; от 1 до 5 млн — дата, альтернативы и позиция нашего предложения; свыше 5 млн — недостающие данные полной формулы. Максимум три вопроса; не спрашивать известное из CRM; без давления при «потом занесу», без вопросов по откреплённым/неперспективным компаниям.
- Отчёт руководителю за период: коммерческие результаты и объёмы, отдельные подтверждённые суммы, суммы в работе и потенциал. Только перспективные закреплённые клиенты, реальные конкуренты/препятствия, следующий шаг и срок. Никаких выдуманных данных.
- CRM: история значений с датами; клиент/филиал/тип/контакты, годовой потенциал по направлениям, сделки и цепочка решения, дополнительные потребности, договорённости. Оценка 0–6 только по подтверждённым фактам; контакт ЛПР и прямой доступ вместе дают один балл. Шестой балл — наше КП направлено.

[Профессиональный контекст](https://app.asana.com/1/1218599458205876/project/1218585786925552/task/1218585786925572) включает `00_system_prompt.md`, `09_assistant_rules.md`, `05_sales_formula.md`, `bot_context.zip`. В прочитанном системном промпте указан максимум один вопрос, а КП в формуле означает конкурентное предложение. Это конфликтует с новым регламентом. До ответа пользователя нельзя выбирать бизнес-правило самостоятельно или отмечать эти пункты выполненными.

[Разговорный стиль](https://app.asana.com/1/1218599458205876/project/1218585786925552/task/1218585786925557), вложение `Pico_стиль_общения_инструкция-2.md`: короткий, живой и деловой тон коллеги; правильная капитализация, короткое тире для списков, 0–2 эмодзи, конкретный следующий шаг, факты отдельно от предположений. В документе также один уточняющий вопрос и описание формирования отчёта; соответствующую логику нужно согласовать с новым регламентом выше. Простая замена нескольких фраз не означает выполнения всей задачи.

### Импорт компаний

[Excel / Google Docs → CRM](https://app.asana.com/1/1218599458205876/project/1218585786925552/task/1218585787061199) имеет только название, без описания и примера файла. Запрошены: Google Таблицы или текстовые Google Документы; перечень данных для поиска; поведение при существующей компании. Нельзя самостоятельно решать, какие пользовательские поля перезаписывать или какие внешние сведения считать подтверждёнными.

### Донаты

[Telegram Stars](https://app.asana.com/1/1218599458205876/project/1218585786925552/task/1218586002021644): показать предложение поддержать Pico после трёх сообщений пользователя, кнопку «⭐️ Задонатить», благодарность после подтверждённой оплаты. Описание содержит тексты предложения и благодарности; вложение — пример кнопки/закрепа. Запрошены суммы Stars и формат выбора. До ответа нельзя выставлять произвольную сумму. Реальная оплата, настройка живого бота и закреп сообщений не выполняются как часть локального тестирования.

## Критерий отметки в Asana

Каждый пункт отмечается только после реализации его согласованного объёма, автоматических проверок и применимой визуальной проверки. Невыполненные интеграционные шаги и вопросы должны оставаться явно открытыми. Локальные тесты используют изолированные данные и тестовые адаптеры; они не подтверждают выкладку или работу реальных Telegram/OpenAI.
