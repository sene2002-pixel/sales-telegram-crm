# Письма по запросу в Telegram

## Голосовая подпись

В личном чате отправьте голосовое, начиная с «Добавь подпись», «Сохрани подпись» или «Создай мою подпись», затем продиктуйте ФИО, рабочий и мобильный телефоны, email. Запись проходит через существующую очередь и сервис распознавания речи; вместо отчёта создаётся личный `signature_drafts`. Бот показывает итоговые данные и кнопки «Подтвердить» / «Отмена». Подтверждение создаёт подпись; отмена очищает черновик. Для исправления доступна CRM → Мой профиль → «Проверить голосовую подпись». Форма позволяет исправить поля и просмотреть расшифровку; «Сохранить изменения» сохраняет подпись, «Отмена» только закрывает форму, «Отклонить черновик» удаляет его содержимое. Лимит три подписи проверяется при сохранении, повторное подтверждение не создаёт дубликат. Основной подписью черновик автоматически не назначается. Неоднозначные данные не дополняются предположениями.

Команды «Измени email в подписи …» и «Сделай подпись … подписью по умолчанию» создают предложения операций `edit` и `default`. При неоднозначном ФИО показываются все подписи с различающими контактными данными. Выбор для редактирования формирует итоговые данные с подтверждением; выбор для назначения основной сразу назначает её после явного предупреждения об эффекте. Однозначное назначение основной требует кнопки подтверждения. Непродиктованные поля редактирования имеют `null` в структурированном ответе и не изменяются; пустая строка означает явно запрошенную очистку. Это соответствует [формату обязательных nullable-полей Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). Сервер проверяет значения, владельца, активность, состояние операции и снимок исходной подписи перед записью. Устаревшее предложение не перезаписывает изменения из профиля.

Распознанные запросы подписи не попадают в список отчётов; данные черновика доступны только автору. После сохранения/отклонения исходная расшифровка, снимки и черновые поля очищаются. В профиле остаются доступны только черновики создания; выбор и подтверждение редактирования/назначения выполняются в Telegram. Голосовые без команды подписи или письма обрабатываются как отчёты о встречах.

## Генерация письма

В личном чате авторизованный сотрудник пишет или произносит `Подготовь письмо для ООО Ромашка`; для текста также доступно `/letter ООО Ромашка`. ИНН и город необязательны, но могут помочь уточнить компанию.
Запросы вида «Напиши информационное письмо для …», «Отправь мне письмо компании …» также распознаются — как текстом, так и голосом. После транскрипции голосовая команда атомарно переносится в очередь писем с исходным ключом дедупликации. Она не становится отчётом о встрече. Голосовые без команды письма или подписи обрабатываются как отчёты.

1. Выбирается личная подпись по умолчанию (или единственная сохранённая). Если подписей несколько без основной, задача сохраняется в состоянии `waiting_signature` и бот показывает список. Предупреждение объясняет, что выбор назначит подпись основной для следующих писем. Выбор назначает основную и переводит задачу в `queued` одной транзакцией. Отмена отменяет задачу без изменения подписи. Повторный callback не меняет выполненный выбор. При изменении/удалении подписи после показа списка нужно отменить старый запрос и отправить новый. Без подписей бот предлагает создать подпись и повторить запрос.
2. Запрос сохраняется в `letter_jobs`, webhook отвечает сразу. Повторный update Telegram не создаёт новую задачу. На сотрудника допускается одна активная задача.
3. Веб-поиск проверяет компанию, ИНН, отрасль и действующего генерального директора. Если он не найден — другого подтверждённого ЛПР. Неоднозначная компания или отсутствие подтверждённого ЛПР останавливают создание: требуется новый запрос с уточнениями. Получатель без ФИО не выдумывается.
4. URL подтверждений сверяются с источниками поискового инструмента. Это проверка происхождения ссылок, не независимая гарантия актуальности сведений.
5. Компания сопоставляется по ИНН, затем по точному названию. Компания вне прав доступа не используется; её контактные данные не раскрываются. Новая компания создаётся на сотрудника. Существующие реквизиты и контакты не перезаписываются.
6. Создаётся одностраничное письмо с референсами ESQ по отрасли. После успешного рендера контакт, файл, аудит источников и готовность задачи сохраняются одной транзакцией. Одинаковое ФИО в компании повторно не добавляется. Телефоны и email не придумываются.
7. PDF отправляется документом только в личный Telegram сотрудника. Клиенту ничего не отправляется. Файл остаётся в CRM.

В профиле у каждой подписи есть кнопка «Сделать по умолчанию». Основная подпись может быть только одна на сотрудника; редактирование сохраняет флаг. При удалении основной другая не назначается произвольно. В ручной форме письма по-прежнему доступен явный выбор подписи.

Обработчик запускается вместе с сервером, когда `WORKER_ENABLED` не выключен. Необходимы `BOT_TOKEN`, `OPENAI_API_KEY` и рабочий генератор PDF. Используется текущая `LETTER_MODEL`.

Задачи имеют 15-минутную аренду и до трёх попыток. После сохранения файла повторяется только доставка, не генерация PDF. После исчерпания попыток бот предлагает скачать файл из компании. При аварии между успешным ответом Telegram и записью статуса возможна повторная доставка того же документа: Telegram sendDocument не предоставляет ключ идемпотентности.

Если генерация не удалась, новая компания может остаться в CRM, но контакт ЛПР без успешно созданного PDF не сохраняется. Источники успешного поиска контакта записываются в `audit` с действием `letter.recipient_verified`; ошибки — в `error_logs`.
