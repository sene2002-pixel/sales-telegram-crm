# Контакт — Telegram CRM

CRM для менеджеров: компании, контакты, проекты, задачи и история общения. Telegram-бот принимает голосовые и текстовые отчёты, формирует проверяемый черновик и сохраняет его в CRM после подтверждения. Руководитель видит команду и назначает ответственных.

## Что нужно для работы

Есть два режима: **локальное знакомство без ключей** и **работа команды через Telegram с ИИ**.

| Что подготовить                 | Локальная CRM                | Telegram + ИИ                            |
| ------------------------------- | ---------------------------- | ---------------------------------------- |
| Git, Node.js 22.12+ и npm       | Да                           | На сервере с Docker Node входит в образ  |
| Python 3.12+ и `.venv`          | Для проверок и скриптов      | Для скриптов резервного копирования      |
| Docker Engine/Desktop с Compose | Нет                          | Для описанного ниже production-запуска   |
| Бот и `BOT_TOKEN`               | Нет                          | Да                                       |
| `OPENAI_API_KEY`                | Только для обработки отчётов | Да, для голосовых и текстовых ИИ-отчётов |
| Публичный домен с HTTPS         | Нет                          | Да: Mini App и webhook                   |
| PostgreSQL                      | Встроенный PGlite            | PostgreSQL 17 в Compose                  |

Отдельные Redis, облачное хранилище, Telegram `api_id`/`api_hash` и GitHub API key приложению не нужны. Очередь находится в SQL, вложения — на диске. Серверу нужен исходящий HTTPS-доступ к Telegram и OpenAI; Telegram должен иметь доступ к публичному webhook.

## Какие ключи получить и куда записать

Все значения записываются в файл `.env` **в корне проекта, рядом с `package.json`**. В браузер, Telegram-чат, GitHub и переменные `VITE_*` секреты не вставляйте. Реальный `.env` исключён из Git; `.env.example` содержит только шаблон.

| Переменная                    | Где получить                                                                                    | Для чего                                              |
| ----------------------------- | ----------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| `BOT_TOKEN`                   | [Официальный BotFather](https://t.me/BotFather), команда `/newbot`                              | Приём/отправка сообщений и проверка Telegram-входа    |
| `OPENAI_API_KEY`              | Проект в [OpenAI Platform](https://platform.openai.com/api-keys), создание секретного API-ключа | Распознавание голоса и выделение данных отчёта        |
| `BOOTSTRAP_ADMIN_TELEGRAM_ID` | Числовой ID вашего Telegram-пользователя                                                        | Первый администратор; это не `@username` и не ID бота |
| `SESSION_SECRET`              | Сгенерировать самостоятельно                                                                    | Подпись сессий CRM                                    |
| `TELEGRAM_WEBHOOK_SECRET`     | Сгенерировать самостоятельно                                                                    | Защита входящих webhook-запросов                      |
| `POSTGRES_PASSWORD`           | Сгенерировать самостоятельно                                                                    | Пароль БД в Docker Compose                            |

### 1. Telegram

Откройте именно `@BotFather`, отправьте `/newbot`, задайте имя и username бота, сохраните выданный токен в `BOT_TOKEN`. Токен позволяет управлять ботом: не публикуйте его. Официальный процесс описан в [инструкции Telegram](https://core.telegram.org/bots/tutorial).

В работающем боте отправьте `/myid` в личном чате: бот ответит вашим числовым Telegram ID, даже если доступ к CRM ещё не выдан. Команда не регистрирует сотрудника и не выдаёт права. Если бот ещё не развёрнут, первоначальный ID можно получить из `message.from.id` собственного Bot API update до регистрации webhook или у доверенного администратора интеграции. Не передавайте токены, пароли или коды входа сторонним ботам. После настройки webhook не запускайте параллельно polling/getUpdates. Запишите свой ID в `BOOTSTRAP_ADMIN_TELEGRAM_ID` до первого входа; смена этой переменной не повышает роль существующего пользователя.

### 2. OpenAI

Создайте ключ нужного проекта OpenAI и сохраните его в `OPENAI_API_KEY`. Хранение ключа на сервере в переменной окружения соответствует [официальному OpenAI Quickstart](https://developers.openai.com/api/docs/quickstart). Проверьте в аккаунте доступ к API, оплату/квоту и разрешения на используемые модели. Пароль от ChatGPT вместо API-ключа не подходит. Доступность моделей и стоимость проверяйте для своего аккаунта перед эксплуатацией.

В текущем коде один ключ используется для двух операций:

- `TRANSCRIPTION_MODEL=gpt-4o-mini-transcribe`: голос → текст, endpoint `/v1/audio/transcriptions`.
- `EXTRACTION_MODEL=gpt-4o-mini`: текст → структурированный черновик, endpoint `/v1/responses`.

Это настройки проекта, а не обещание доступности моделей в любом аккаунте. Другого провайдера нельзя подключить простой подстановкой его ключа: текущий адаптер обращается к `api.openai.com`. Голос и текст отчёта передаются внешнему ИИ-провайдеру; согласуйте допустимость передачи клиентских данных. Без ключа ручное ведение CRM доступно, но подготовка ИИ-отчётов не работает.

### 3. Собственные секреты

Выполните команду **три раза**, каждый раз сохраните новое значение в отдельную переменную: `SESSION_SECRET`, `TELEGRAM_WEBHOOK_SECRET`, `POSTGRES_PASSWORD`.

```sh
openssl rand -hex 32
```

Это не платные API-ключи. Hex-строки подходят для webhook и подключения PostgreSQL. Не используйте одинаковый секрет для разных целей. В production первые два секрета должны быть не короче 32 символов. Не присылайте полученные значения в переписку.

## Локальный запуск без Telegram и ИИ

Требуется Node.js 22.12+ и Python 3.12+. Docker для локальной разработки не нужен.

```sh
git clone https://github.com/sene2002-pixel/sales-telegram-crm.git
cd sales-telegram-crm
# До слияния PR реализация находится в этой ветке:
git switch feat/telegram-crm-platform
python3 -m venv .venv
source .venv/bin/activate
npm ci
cp -n .env.example .env
npm run build
npm start
```

Команды рассчитаны на macOS/Linux (Windows — WSL). Если репозиторий уже скачан, начните из его каталога, не клонируйте повторно. `cp -n` не перезаписывает существующий `.env`. Для сборки и браузера на порту 3000 установите в нём `PUBLIC_URL=http://localhost:3000`; `DEV_AUTH=true`, остальные локальные значения можно оставить из шаблона.

Откройте http://localhost:3000. В `.env` для локального входа должно быть `DEV_AUTH=true`. На экране доступны отдельные демонстрационные роли; их данные не являются фиктивной заменой API — все изменения сохраняются в локальной БД `data/postgres`.

Для разработки с горячим обновлением сначала выполните `npm run build:server`, затем `npm run dev`; интерфейс на http://localhost:5173. Настройка `PUBLIC_URL` относится к кнопкам бота, а не к адресу слушателя API.

Python-окружение `.venv` используется для скриптов резервного копирования (только стандартная библиотека, pip-зависимостей нет). TypeScript-зависимости изолированы в `node_modules`. Оба каталога исключены из Git.

Секреты живут только в `.env`. Без `OPENAI_API_KEY` ручная CRM работает, а обработка отчёта завершится понятной ошибкой конфигурации. Демонстрационный вход никогда не разрешён в production.

Остановить локальный сервер: `Ctrl+C`; повторно запустить: `npm start`. После изменения `.env` перезапустите процесс. Без постоянного `SESSION_SECRET` локальные сессии перестанут действовать после перезапуска — просто войдите заново.

## Запуск для команды: Docker, HTTPS и Telegram

### 1. Подготовьте сервер и `.env`

Скачайте репозиторий, установите Docker с Compose и Python, создайте `.venv` как выше. На Docker-сервере `npm ci` и сборка вручную не нужны: их выполняет Dockerfile. Используйте отдельную установку/данные для production, не демонстрационную БД.

Скопируйте `.env.example` в `.env` без перезаписи существующего файла и заполните следующие поля. Значения `REPLACE_...` — заглушки, их обязательно заменить; ID `123456789` тоже пример.

```dotenv
NODE_ENV=production
DEV_AUTH=false
HOST=0.0.0.0
PORT=3000
PUBLIC_URL=https://crm.example.com
BOT_TOKEN=REPLACE_WITH_BOTFATHER_TOKEN
BOOTSTRAP_ADMIN_TELEGRAM_ID=123456789
OPENAI_API_KEY=REPLACE_WITH_OPENAI_API_KEY
SESSION_SECRET=REPLACE_WITH_UNIQUE_RANDOM_HEX
TELEGRAM_WEBHOOK_SECRET=REPLACE_WITH_ANOTHER_RANDOM_HEX
POSTGRES_PASSWORD=REPLACE_WITH_THIRD_RANDOM_HEX
TRANSCRIPTION_MODEL=gpt-4o-mini-transcribe
EXTRACTION_MODEL=gpt-4o-mini
WORKER_ENABLED=true
REPORT_TIMEZONE=Europe/Moscow
```

Compose автоматически задаёт `DATABASE_URL` и `DATA_DIR` внутри контейнера. При запуске без Compose потребуется отдельный PostgreSQL и `DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/DATABASE`. Пустой `DATABASE_URL` в production запрещён. Не открывайте порт PostgreSQL в интернет.

### 2. Запустите контейнеры

```sh
mkdir -p data/files
# На Linux: дать пользователю контейнера права на каталог вложений.
sudo chown 1000:1000 data/files
docker compose up -d --build
docker compose ps
curl --fail http://127.0.0.1:3000/api/health
```

`chown` выполняйте только для указанного каталога своей установки. PostgreSQL хранится в Docker volume `postgres_data`, вложения — в `data/files`. Миграции создаются автоматически при старте. Health проверяет SQL, но не действительность внешних API-ключей.

### 3. Настройте HTTPS

Направьте DNS домена на сервер, установите TLS-сертификат и настройте reverse proxy: весь сайт `/` и `/api` должен идти на `http://127.0.0.1:3000` без изменения путей. Разрешите тело запроса до 11 МБ для загрузки файлов. Конкретная настройка proxy зависит от вашей инфраструктуры; Compose сам сертификат и DNS не создаёт.

Проверьте `https://ВАШ-ДОМЕН/api/health` с другого устройства. В `PUBLIC_URL` должен быть этот публичный HTTPS-адрес **без завершающего слеша**, не localhost. Не публикуйте демо-режим с `DEV_AUTH=true`.

### 4. Зарегистрируйте webhook и войдите

```sh
docker compose exec app node dist/server/setup-telegram.js
```

Скрипт устанавливает команды `/start`, `/help`, `/crm`, `/tasks`, кнопку «Открыть CRM» и webhook `${PUBLIC_URL}/api/telegram/webhook`. Он изменяет настройки именно бота из `BOT_TOKEN`; для тестов используйте отдельного бота. При смене домена повторите настройку. Для запуска без Docker после сборки эквивалентная команда — `npm run telegram:setup`.

Откройте личный чат бота под аккаунтом с указанным bootstrap ID → `/start` → `/crm` → «Открыть CRM». Обычная вкладка браузера без Telegram-входа не заменяет Mini App. В «Команда» → «Доступ сотрудников» добавьте числовые ID коллег и назначьте роли — [пошаговый гайд](docs/ROLE_GUIDE.md).

### 5. Проверьте первую встречу

Надиктуйте: «Компания Альфа, встреча сегодня. Обсудили поставку. Контакт Иван. Подготовить предложение завтра». Дождитесь черновика, откройте «Отчёты», проверьте компанию и сроки, подтвердите. Только после подтверждения итог попадает в «История» компании, контакты — в «Контакты», поручения — в «Задачи». Транскрипция и черновик сохраняются в SQL-записи отчёта. Не проверяйте точность ИИ на реальных данных без согласования.

## Все остальные настройки

| Переменная          | Значение по умолчанию / смысл                                                                           |
| ------------------- | ------------------------------------------------------------------------------------------------------- |
| `PORT`, `HOST`      | `3000`, `127.0.0.1` для локального API; Compose переопределяет HOST                                     |
| `PUBLIC_URL`        | В шаблоне `http://localhost:5173` для Vite; для `npm start` — порт 3000, для Telegram — публичный HTTPS |
| `DATABASE_URL`      | Пусто: локальный PGlite; production: обязательный PostgreSQL                                            |
| `DATA_DIR`          | `./data`: локальная БД и вложения; в Compose `/app/data`                                                |
| `WORKER_ENABLED`    | `true`: обработка очереди; при `false` отчёты остаются в очереди                                        |
| `REPORT_TIMEZONE`   | `Europe/Moscow`: интерпретация относительных дат в отчётах                                              |
| `MAX_VOICE_SECONDS` | `600`: максимальная длительность голосового сообщения                                                   |
| `MAX_VOICE_BYTES`   | `20000000`: максимальный размер голосового сообщения в байтах                                           |

Размер обычного файла-вложения ограничен в коде 10 МБ, это не `MAX_VOICE_BYTES`.

## Перезапуск, логи и частые проблемы

```sh
docker compose logs --tail=100 app
# После изменения .env: пересоздать app с новыми переменными.
docker compose up -d --force-recreate app
# После обновления кода:
docker compose up -d --build
# Остановить без удаления данных:
docker compose stop
```

`docker compose restart` не подхватывает изменённые переменные контейнера. Не используйте `docker compose down -v`: это удаляет volume базы. Не удаляйте `data/` для «починки». До обновлений делайте [резервную копию по инструкции](docs/OPERATIONS.md).

| Симптом                          | Что проверить                                                                                                  |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Сервис не стартует в production  | PostgreSQL, HTTPS PUBLIC_URL, bootstrap ID, оба длинных секрета, BOT_TOKEN и DEV_AUTH=false                    |
| Бот молчит                       | Контейнер app, токен, публичный HTTPS, выполненную регистрацию webhook, личный чат, активный доступ сотрудника |
| «Не настроен OPENAI_API_KEY»     | Ключ в серверном `.env`, пересоздание контейнера после изменения                                               |
| Ошибка ИИ HTTP 401/403/429       | Действительность ключа, разрешения/доступ аккаунта, квоты и ограничения провайдера; не выводите ключ в логи    |
| Отчёт долго «В очереди»          | WORKER_ENABLED=true, работа app, доступ к БД и внешним API                                                     |
| Администратор не получает доступ | Именно пользовательский числовой Telegram ID; для существующей учётки — текущая роль и active                  |
| Локально занят порт 3000         | Остановить свой старый процесс или изменить PORT; для Vite также согласовать proxy в vite.config.mts           |
| Не загружается файл              | Лимит 10 МБ, права data/files, лимит reverse proxy, компания не в архиве                                       |

При утечке отзовите соответствующий ключ у провайдера, замените в `.env` и пересоздайте app. Изменение webhook-секрета также требует повторного запуска setup-telegram. Проверки реального Telegram, ИИ, HTTPS и восстановления данных выполняются отдельно — автоматические тесты не подтверждают готовность инфраструктуры.

## Проверка

```sh
npm run check
npm run test:ops
npx playwright install chromium
npm run test:e2e
.venv/bin/python scripts/backup.py --help
```

Тесты используют отдельную временную базу и не меняют рабочие данные. Тесты провайдеров не делают платных запросов. Для проверки реального бота нужны пользовательские токены и публичный HTTPS — см. эксплуатационную инструкцию.

## Структура

```text
src/shared/       Схемы данных и контракты
src/server/
  domain/        Ошибки и инварианты
  services/      Авторизация, CRM, отчёты, бот, очередь, аналитика
  infra/         SQL, миграции, аудит, Telegram и ИИ-адаптеры
  http/          NestJS-контроллеры, guards, composition root
src/web/         React Mini App
src/tests/       Проверки бизнес-сценариев и HTTP
e2e/             Браузерные сценарии
scripts/         Эксплуатационные инструменты Python
app.jsx          Сохранённый исходный прототип, в сборку не входит
```

Работа ведётся в feature-ветке. Для слияния используйте pull request; прямой push в `main` не требуется.
